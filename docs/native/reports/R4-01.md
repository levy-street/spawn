# R4-01 — Global app chrome

## What I built

- Added the frozen `AppHeader` API with a solid themed background, one safe-area top inset, centred title/subtitle, equal fixed side slots, a standard ghost `ChevronLeft` back action, up to three centred ghost actions, accessory support, and a themed divider.
- Added full-bleed `Screen.header` composition for both static and keyboard-aware screens. Header-bearing content no longer adds its own top inset, and `HeaderHeightContext` is gone from the shared layout.
- Disabled the native drawer-stack header app-wide while preserving card presentation and full-screen horizontal back gestures. `APP_ROUTE_MAP` and `FULL_SCREEN_BACK_OPTIONS` remain exported.
- Painted onboarding stack scenes with `theme.colors.background` while retaining its existing headerless gesture configuration.
- Replaced the rendered `HeaderDestinations` component with `headerDestinationActions(destinations): readonly AppHeaderAction[]`, backed by Expo Router's global router.
- Added behaviour coverage for title/subtitle, back, enabled and disabled actions, equal side-slot reservation, header/inset composition, keyboard-screen threading, and destination navigation.

## Deviations and why

None. The frozen interfaces and sizing tokens were used unchanged. `AppHeader` reads `SafeAreaInsetsContext` with a zero-token fallback so isolated render tests do not require a provider; the real app provider still supplies the device insets.
