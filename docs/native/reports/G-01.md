# G-01 — navigation scaffold and authenticated identity lifecycle

## What I built

- Removed the runtime drawer navigator, all burger/menu UI, its drawer-only tests, and the direct
  `@react-navigation/drawer` dependency from `mobile/package.json`.
- Replaced the nested drawer stacks with one protected native stack. Workspaces is its initial
  route; Hosts, Legion, Settings, and Admin are direct pushed routes with native back buttons.
- Added direct header destination buttons instead of a menu. The navigation graph exposes Hosts
  and Settings from Workspaces, Legion from Hosts, and Admin from Settings; each destination can
  reach the other roots and return through the native stack.
- Preserved the existing public URLs in `APP_ROUTE_MAP`, including every settings/admin drill-in,
  host/files route, workspace detail, and archived workspaces route.
- Enabled pushed-card dismissal with `presentation: "card"`, `gestureEnabled: true`,
  `gestureDirection: "horizontal"`, and `fullScreenGestureEnabled: true` on the protected stack,
  root cards, auth stack, and onboarding stack. Removed the terminal route's local
  `gestureEnabled: false` override; G-06 still owns the loaded terminal overlay gesture hierarchy.
- Added the frozen `Screen` API. Ordinary native-header routes do not add another top inset;
  headerless routes add it once. The scaffold centralises the standard gutter, left/right safe
  areas, bottom safety, deterministic scroll insets, interactive keyboard dismissal, focused-field
  avoidance, measured footer clearance, `KeyboardStickyView`, and G-02's `FooterActions`.
- Converted every G-01-owned ordinary route wrapper plus onboarding and terminal loading/error
  states to `Screen`. Onboarding no longer stacks `KeyboardAvoidingView`, automatic keyboard
  insets, and safe-area wrappers.
- Made `AuthGate` the device-identity account authority. It binds synchronously from
  `me.user.id`, gates the protected stack until binding is complete, clears selection on token
  changes/logout/server changes/401, and clears A before selecting B. It never calls
  `deviceIdentity.reset()` during ordinary logout or switching.
- Added behavioral tests for the stable route/link map, absence of drawer routes, full-screen
  gesture options, direct header navigation, single top-inset ownership, keyboard footer policy,
  account selection/clearing, A→B ordering, and signing-before-binding prevention.

## Safe-area ownership invariant

- Ordinary signed-in routes: the native-stack header is the sole top/status-bar inset owner;
  `Screen` applies `paddingTop: 0` when the header-height context is nonzero.
- Headerless routes: `Screen` is the sole top inset owner.
- Footer routes: `FooterActions` owns the safe bottom while `KeyboardStickyView` owns keyboard
  translation; scroll content reserves the measured footer but does not add the safe bottom again.
- Overlays remain responsible for their own full-window geometry and were not modified.

## Deviations from the plan

1. The URL-invisible route-group directory is still named `(drawer)` even though it now contains a
   plain `Stack` and no drawer code. Renaming the group would break cross-owned imports in
   `workspace-detail/__tests__/route.test.tsx`, `settings/__tests__/server-connectivity.test.tsx`,
   and the already-stale app-shell test. The runtime navigator, menu, burger controls, drawer
   actions, drawer content, and direct dependency are all gone.
2. Existing auth form components retain their legitimate headerless `AuthShell` safe-area owner;
   wrapping them in `Screen` without changing `components/auth/**` would double the inset. The
   signed-out server route and all onboarding routes were converted within G-01 ownership.
3. The terminal's loaded overlay remains G-06's responsibility. G-01 removed the route-level
   gesture disable and standardized terminal loading/error states, but did not modify the custom
   overlay or WebView gesture recognizers.
4. `mobile/package-lock.json` was not edited, per path ownership. It still contains the drawer
   dependency until the orchestrator reconciles it.
