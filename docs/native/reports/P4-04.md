# P4-04 — Production network adapter and notification preference consolidation

## What I built

### Socket-aware production network fallback

- Added `createProductionNetworkSource()` and made it the default source in `RealtimeProvider` when
  tests or callers do not inject a richer `NetworkSource`.
- Preserved injected-source behavior for deterministic tests and for a future native reachability
  implementation.
- Converted an established alert socket's unexpected `open -> reconnecting` transition into a
  process-local network epoch. The lifecycle coordinator handles that epoch as an interface change:
  it retires sockets and registered RTC generations before reconnecting, refetching, and reopening
  visible transports.
- Coalesced repeated failures in one reconnect episode until the socket opens again, preventing a
  reconnect loop.
- Left AppState ownership in the existing lifecycle coordinator, which already retires on
  background and performs the ordered active-state sweep.

The fixed dependency set contains neither `expo-network` nor
`@react-native-community/netinfo`. The fallback therefore cannot directly observe Wi-Fi/cellular
interface changes. It is deliberately named and documented as socket-observed recovery rather than
pretending to provide native reachability.

### One live notification preference authority

- Changed `NotificationsPanel` to consume `@/data/queries/alerts`'s
  `useNotificationPreferences()`, which is backed by the same observable store in
  `@/lib/notifications` that `AlertPresenter` reads at delivery time.
- Preserved the panel's existing skeleton, inline storage-error placement, copy, layout, and
  controls; only its data source changed.
- A setting toggle now updates the in-process snapshot immediately and persists the unchanged
  eight-field schema under the unchanged `spawn.notify.prefs` key. The next presenter alert sees
  the new value without a restart.
- `mobile/src/lib/notifications.ts` already implemented the required observable store and needed no
  source change.

## Deviations from the plan

1. A true native reachability/interface adapter was not achievable from the frozen dependency set.
   The implemented fallback combines the existing AppState policy with socket-failure epochs. It
   gives hard recovery once the socket detects a dead path, but not proactive Wi-Fi-to-cellular
   detection. Adding a dependency was explicitly forbidden.
2. The final whole-tree typecheck, lint, and test commands were not green because files owned by a
   concurrent terminal-transport agent were incomplete. Focused checks and tests for every P4-04
   file are clean; no out-of-scope file was changed.

## Known gaps

- A silent Wi-Fi/cellular handoff is not observable until AppState changes or an established socket
  fails/reaches its watchdog. The alert watchdog can make that delay as long as 80 seconds.
- The fallback cannot distinguish internet loss from a server-specific socket failure; it keeps
  TanStack's online state optimistic and relies on normal reconnect backoff.
- Legacy settings preference modules remain in the tree because they are outside P4-04 ownership,
  although Notifications Settings and the presenter now have one live authority.
- No simulator, Expo Go, physical-device, or manual network-handoff testing was performed, per the
  campaign rules.
