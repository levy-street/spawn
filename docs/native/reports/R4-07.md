# R4-07 — Workspace tabs and header actions

## What I built

- Rebuilt workspace tabs from the frozen `sizing.tab` contract: tokenized native tab width/height/gaps, muted resting surfaces, foreground active labels, a persistent close affordance with a 44pt target and 20pt visual plate, and the global attention-count badge before the label.
- Added the web-parity connected treatment. A populated active tab grows by `connectionOverlap`, overlaps the pane surface, and renders two `connectionRadius` surface squares with background-coloured circular cutouts to form the concave flares.
- Preserved the existing long-press reorder gesture, sibling translation, edge auto-scroll, insertion indicator, haptics, accessibility announcements/actions, and end-of-strip add button.
- Replaced the native-stack `navigation.setOptions` side effect with an in-scene `WorkspaceHeader` backed by the global `AppHeader`: workspace title, standard back action, launcher `+`, and workspace-actions `…`.
- Made `WorkspaceDetail` own its global `Screen` and pass the workspace header through `Screen.header`; loading and unavailable states also receive a global fallback header. The route is now only responsible for URL navigation.
- Audited the sheet path. `LauncherSheet` and `WorkspaceActionsSheet` were already mounted unconditionally with correct `visible` state; the lost native header was the root cause. No sheet implementation fix was needed.
- Replaced the owned pane list's local spacer separator with global `ListSeparator` and consumed `ListRow shape="fullBleed"` across terminal, files, and missing-pane rows.
- Added behavior/render coverage for connected flare geometry, tokenized close controls, attention, back/header callbacks, and both header actions making their mounted sheets visible.

The `impeccable` guidance kept this parity pass restrained: the existing web treatment and frozen native tokens determined the visuals, while interaction and surface decisions remained in global primitives.
