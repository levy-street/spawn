# P2-10 — Session launcher

## What I built

Implemented everything owned by P2-10 between tapping the new-session action and opening the
created terminal:

- A native four-step `LauncherSheet`: host → folder → shell/agent → optional name/target tab.
- Online/paired host selection with presence, CPU/memory buckets, and session-row telemetry shown
  as information only.
- A phone-shaped folder picker using the host-control WebView transport: recent directories,
  single-column drill-down, home-rooted breadcrumbs, direct path entry with `purpose="path"`,
  current-folder search, a persisted hidden-folder preference, and a sticky choose action.
- Exact directory filtering semantics: directories only, dot-directories hidden by default,
  case-insensitive filter/sort, and at most 12 drained `fs.list` pages.
- Exact POSIX shell quoting, environment prefixes, yolo arguments/environment, install-and-run
  construction, and built-in-before-custom agent ordering.
- Two-stage agent launch orchestration: patch the freshest workspace to the intended active tab,
  reshape/place from the authoritative layout algebra, create a login-shell Session, then persist
  the command for terminal-ready delivery.
- Chunked SecureStore persistence for pending commands, preserving secrets and commands larger than
  one safe SecureStore value. Records are consumed exactly once, expire, survive process restart,
  and distinguish missing, stale, corrupt/lost, and ready states.
- Honest partial-failure UI after Session creation: keep the bare shell or remove it. Cancellation
  during an in-flight launch also removes a subsequently created Session.
- Ported shell handoff: destructive confirmation, at most eight 700 ms polls, Ctrl-C on only the
  first four attempts, fresh Session reads, clear-before-command after handoff, and an honest busy
  result.
- Selection/success/error haptics at the specified semantic boundaries.

## Exported integration API

P2-04 can present:

```tsx
<LauncherSheet
  visible={visible}
  workspaceId={workspaceId}
  initialTabId={activeTabId}
  onDismiss={closeLauncher}
  onLaunched={({ session, pendingCommand, warning }) => {
    // Navigate to P2-05's terminal route with session.id.
  }}
  onLaunchError={(message, sessionId) => {
    // Optional caller-level error reporting.
  }}
/>
```

Exports used at the terminal boundary:

- `deliverPendingLaunch(sessionId, terminal)` from `@/data/queries/launcher`; call only after the
  terminal transport is ready. It returns `sent | missing | stale | lost` and never hides a saved
  command read/send failure.
- `useShellHandoff()` from `@/components/launcher/use-shell-handoff`; accepts the current Session,
  a `{sendInput, focus}` terminal adapter, command, and purpose.
- `useLaunchSession()`, `useLauncherData()`, and `useRecentDirectories()` are available when a
  caller needs the lower-level hooks instead of `LauncherSheet`.

## Deviations from the plan

- The plan required stale durable launches but did not choose an expiry. I used 15 minutes: long
  enough for a normal terminal connection/relaunch, bounded enough not to replay an old secret
  command much later.
- Recent directories use a picker-lifetime async hook rather than TanStack Query because the frozen
  `qk` registry has no recent-directory key and P2-10 does not own it. Results are neither persisted
  nor mixed with host-control directory listings.
- Precise protocol-code folder errors are implemented in the picker mapper, but the current
  `HostTransport.request()` implementation discards `error.code` and rejects a plain `Error`.
  Generic/detail text is therefore shown until that transport boundary preserves the code.
