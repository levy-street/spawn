# P3-02 — Long tail implementation report

## What I built

- **F-020 / F-033 — Archived workspaces.** Added the `/workspaces/archived` native route with a
  newest-first list, loading/error/empty/refresh states, retained-layout entry, Restore, and
  permanently Delete. The screen consistently explains that archive suspends a workspace, retains
  its sessions/layout, and restarts those same sessions where hosts are online after restore.
- **F-004 / F-005 / F-120 — About, install, and security.** Added a compact operational About
  surface with the app version, MIT/Apache licensing, deployment-specific standard and
  prebuilt-only install commands, copy/share behavior, the server-as-adversary security summary,
  and Security, Download, and source links.
- **F-105–F-108 — Admin.** Added a real, plain native admin stack rather than a stub. It gates the
  entire stack on `me.user.is_admin`; non-admin content never mounts. It includes section entry,
  invitation creation/revocation (optional email, 1–720 hour TTL, one-time URL copy/dismiss), the
  complete read-only user fields, mail delivery status, `{to:null}` test delivery, and expandable
  redacted email records.
- Added TanStack Query hooks and cache updates for all admin reads and mutations.
- Added behavioral tests for admin authorization, invite input/badges/cache updates, user and email
  rendering, archived restore/delete copy, About version/install/security content, and clipboard
  behavior. P3-02 owns 5 suites and 11 tests.

## Capability cross-check and remaining-gap handoff

I read `research/06` end to end and cross-referenced every Phase 2 report, then checked current
call sites for the cross-owner handoffs those reports identified. P3-02 closes F-004, F-005,
F-020, F-033's archived-collection restore/delete side, and F-105–F-108. F-120's component is
complete but needs the Settings-owned route described below.

The following gaps remain outside P3-02's owned paths and should be carried into P3-06:

### Trust and application shell

- **F-013 / F-083:** the pairing response has no ceremony-created/expiry timestamp, so the native
  countdown is a conservative local 30-minute review window rather than exact daemon-relative
  expiry.
- **F-015:** registration repair exists in Browser Devices settings, but the researched global
  device-registration health banner is not mounted in the authenticated shell.
- **F-103:** verified introductions can be imported into local pins, but the API has no consumed
  endorsement acknowledgement/deletion endpoint.

### Workspaces, tabs, and sessions

- **F-024 / F-026:** selected-tab state is local to the mounted detail screen; per-workspace tab
  restoration and global last-opened workspace persistence are not wired. The archived detail
  state also lacks its banner (F-050).
- **F-025:** the detail workspace menu exposes Rename and Add tab. Change icon, set default
  host/folder, Save as template, Archive, and Delete are not exposed there; archive/delete remain
  reachable from the workspace list.
- **F-028 / F-029:** tab reorder/rename/delete work, but tab duplication and tab-specific inherited
  versus explicit host/folder editing are absent.
- **F-031 / F-032:** valid saved-home templates replay, but an offline/missing remembered host has
  no relocate-before-replay picker. Icon editing is manual only; folder scanning, suggestions, and
  resize/transcode are absent.
- **F-039:** saving the current workspace as a template is absent.
- **F-041 / F-043:** ordered phone rows support move up/down, move-to-tab, duplicate-in-place, and
  close. The explicit “Layout on desktop” explanation/presets and Duplicate-to-tab destination
  sheet are absent.
- **F-045 / F-046:** rename/restart/duplicate/reorder/close are present. The pane-level agent
  switcher, change host, `cd` folder change, mute control, and move-session-to-host flow are absent.
- **F-047 / F-049:** launcher/session creation is mounted, and durable command/handoff helpers
  exist, but no terminal-ready call site invokes `deliverPendingLaunch`; shell/agent/files switching
  and controlled running-agent handoff are not mounted.
- **F-050:** an archived workspace can be opened and restored from the collection, but its detail
  screen has no archived/stopped banner or inline Restore action.

### Terminal

- **F-056:** `take_control` is represented in the low-level codec, but shared-view ownership and a
  Take control UI are absent.
- **F-058:** the native diagnostics sheet reports worker/security/renderer health, but not the
  researched direct-vs-relay path, RTT, or verified/first-contact trust detail.
- **F-060:** attachment transport types exist, but clipboard-image detection, ready/error chips,
  deferred `@path` insertion, and image removal/consumption UI are absent.
- **F-061:** explicit selection/copy and text paste exist; adjustable native handles and a
  `TerminalSurface` paste command with bracketed-paste semantics remain blocked by the frozen
  surface contract.
- **F-063 / F-064:** opt-in predictive echo, latency HUD, renderer override, and the six-entry warm
  live-terminal LRU are absent. Each terminal route currently owns one live surface.
- **F-065:** terminal chrome has no swipe-dismissable Files overlay rooted at the session cwd.
- **F-066:** Composer remains intentionally unplaced because research found no product call site;
  P3-06 should retain this as an explicit reachability decision, not silently call it complete.

### Files and host control

- **F-068 / F-076:** the phone-native current-directory browser deliberately replaces the desktop
  expansion tree, but long press opens row actions rather than the researched Quick Look sheet.
  P3-06 should decide whether the missing pinned-preview gesture is an acceptable native adaptation.
- **F-069:** file-tree hardware-keyboard navigation is absent.
- **F-071 / F-072 / F-077 / F-078:** upload picking is not surfaced, and preview/download/share
  byte paths are runtime-blocked. Viewer, safe renderer, local sink, progress, and cancellation
  code exists, but cannot activate until host stream frames are exposed.
- **F-074 / F-075 / F-079:** source-to-destination transfer primitives exist without a Send to
  host action. Row actions omit Copy relative path, Reveal on host, and Open on host.
- **F-078:** the bounded native Markdown renderer is intentionally GFM-shaped rather than a full
  nested-GFM parser because the fixed dependency set omits the approved parser packages. PDF/media
  codec behavior still needs the required physical-iPhone check.
- **F-080 / F-116:** `HostTransport` still lacks advertised capabilities and verified read/write
  stream operations, drops stream frames, and collapses structured daemon error codes. This blocks
  exact preflight, exact permission/symlink copy, files byte operations, transfers, and host upload.

### Settings, alerts, identity, and input

- **F-094 / F-115:** the alert presenter is mounted, but Settings and delivery still use duplicate
  notification-preference stores. Settings changes may not update the presenter snapshot until
  restart, and the current System row disables local notifications along with unavailable remote
  push. Workspace/tab/session surfaces have not adopted the shared `AttentionBadge` precedence.
- **F-098:** template image selection is bounded but not rasterized and has no host-folder image
  suggestions.
- **F-105 / F-120:** `/admin` is guarded and About is implemented, but neither has a Settings row;
  About also lacks a Settings-owned route. This is a path-ownership integration gap.
- **F-114:** file/workspace icon mapping exists, but some agent artwork/color is still a semantic
  approximation and the exact app brand assets are owned by the concurrent shell/asset pass.
- **F-119:** raw terminal keys and the modifier bar are present, but the wider file tree, folder
  picker, menu, rename, grid, and tab hardware-keyboard contract is incomplete.

Accepted Expo Go constraints remain explicit rather than disguised as parity: OAuth redirects for
F-007/F-008, passkey-PRF backup for F-101, and suspended/terminated remote push for F-094. Local
notifications and direct pairing/endorsement are the supported paths.

## Deviations from the plan and research

1. The plan cites `research/12 §6` for Admin, but the current report's Admin specification is §15
   (public/download material is §16). I used the actual sections; the requirements themselves were
   not contradictory.
2. The About component could not be given a route or Settings row because P3-02 owns no Settings
   route or component path. I stopped at the reusable screen instead of violating ownership.
3. The Admin stack likewise has no Settings entry point yet. Direct `/admin` access is correctly
   gated, so non-admins cannot mount protected content, but admins need the requested row for normal
   discoverability.
4. Research did not name the canonical source repository URL. I consulted the reference web source
   only for `https://github.com/levy-street/spawn`; no research contradiction was found.
5. Public landing masthead/motion (F-002/F-003) was not ported wholesale. This follows P3-02 and
   F-120's explicit requirement for compact operational About content rather than desktop marketing
   animation.
6. The design-context skill's project file would live outside P3-02's allowed paths, so no shared
   `.impeccable.md` was created. The frozen native theme, research tokens, and existing shared
   components supplied the required project context instead.
