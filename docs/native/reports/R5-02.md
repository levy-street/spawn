# R5-02 — Bottom drawers and full-page modals

## What I built

- Made `Sheet` the single bottom-drawer presentation: it lazily mounts, reaches the bottom edge, has top-only rounded corners and a visible grabber, enables pan-down dismissal, closes from its backdrop, and pads its content above the home indicator.
- Routed `Popover`, `Menu`, and `NativePopover` through `Sheet`. Existing anchor, side, alignment, and width props remain source-compatible, but no longer create anchored floating geometry.
- Kept long menu/select lists on the bottom-sheet-aware scroll view so the list gesture and drawer gesture can coordinate.
- Replaced the centred `Dialog` card and scrim with a full-screen modal surface. Every size now renders full-page, with its title/copy at the top, content filling the middle, and declared actions pinned through the shared keyboard-aware `FooterActions`.
- Flattened fragment-based dialog footers before passing them to `FooterActions`, preserving the existing equal-width two-action layout used by confirms and rename dialogs.
- Fixed the New workspace dead space at its source. `Dialog` now charges the top safe-area inset once in its header, then supplies a zero top inset to nested full-page content; the nested `Screen` no longer charges the same inset a second time. The real bottom inset remains available to nested/shared footers.
- Added explicit behavior coverage for drag-down dismissal, backdrop dismissal, bottom-edge/safe-area geometry, full-page dialog geometry, pinned actions, and the single top-inset contract.

The `impeccable` pass kept the change at the global primitives, removed the nested card treatment inside drawers, and preserved the product's existing themed surfaces and control hierarchy.

## Deviations and why

- All exported component prop interfaces remain intact. Popover anchor/position props are intentionally presentation no-ops now because the product requires every popover to use the same bottom drawer.
- `Dialog.size` remains accepted for call-site compatibility, but every value intentionally resolves to the required full-page presentation.
- No sizing token was added: the implementation uses existing theme spacing, radius, border, safe-area, and footer tokens.
- No consumer production file outside R5-02 ownership was edited.
- No simulator, Expo Go, screenshot, or manual-device testing was performed, per the round rules.
