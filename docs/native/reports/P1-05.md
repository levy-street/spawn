# P1-05 — API client, auth token store, schemas, and endpoints

## What I built

Implemented the complete framework-free `@/data/api` layer:

- A 30-second-timeout fetch client with per-request overrides, bearer injection, caller abort
  propagation, JSON/text/ArrayBuffer responses, FastAPI error normalization, 204 handling, zod
  response validation, schema-mismatch diagnostics, and no retry layer.
- A deduplicated app-level unauthenticated event. An authenticated 401 clears the durable token and
  emits once until a later authenticated request starts a new session generation.
- The campaign's bearer-from-`set-cookie` decision: capture only the 30-day `spawn_session` JWT,
  decode `exp` without verification, persist the token and expiry through the shared SecureStore
  wrapper, cache them in memory, reject hard-expired tokens, and namespace credentials by server.
- Persisted base URL resolution: runtime override, then `expo.extra.apiUrl`, then the compiled
  development default. Runtime values are normalized and restricted to credential-free HTTP(S).
- Zod request/response schemas and inferred snake_case TypeScript types for every documented wire
  type, preserving nullable versus optional fields.
- One typed operation for all 79 HTTP routes, including the otherwise unavailable OAuth redirects
  as URL builders and the public installer binary/text routes.
- Authenticated `ws(s)` URL builders for browser signalling, host signalling, and alerts.

`onResponse`. The last hook is what captures `set-cookie` before the login response body is parsed.

## Deviations and research corrections

1. `research/03` says the native app needs a new refresh endpoint and its copy-ready client stores
   the JSON `access_token`. The campaign overview and this plan supersede that conclusion with a
   direct source verification: React Native captures the 30-day `spawn_session` value from
   `set-cookie`, and that JWT is accepted as a bearer. Only that long token is stored.
2. The research client retries safe GETs and defaults to 15 seconds. The assignment explicitly
   prohibits a client retry layer and requires 30 seconds, so there are no retries and React Query
   remains the sole retry owner.
3. OAuth route operations return fully encoded URLs rather than following the 302 responses.
   Expo Go cannot complete the server's web-relative callback into the app; the functions retain
   typed route parity for a browser/diagnostic caller and are marked with that limitation.
4. Schemas are split by actual shared wire responsibility rather than creating empty parallel
   `capabilities` or `account` schema files. Session access schemas live with skills, while account
   request/response schemas live with auth. Endpoint modules remain direct imports with no barrel.

## Base URL decision

The production API origin is still owner input. The compiled fallback is
`http://localhost:8000`, useful only for local tooling; a physical iPhone must be pointed at a
reachable HTTPS origin through `setBaseUrl`. A persisted override wins over `app.json`'s optional
`expo.extra.apiUrl`, which wins over that fallback. Tokens are namespaced by normalized base URL so
credentials from server A are never sent to server B.
