# P3-06 — Native parity audit

## Verdict

The mobile client contains a substantial native implementation, but it is not at feature parity with the 121-capability contract. The control-plane experience—authentication, workspace navigation, host management, settings, and most CRUD—is the strongest area. The headline terminal path is implemented in code but remains device-unverified, and several surrounding capabilities that make it a complete spawn client are missing: shared terminal ownership, the warm-terminal pool, pending agent-command delivery, clipboard images, terminal Files, host-control stream/capability support, Files upload/transfer, and hardware-keyboard navigation.

“Done” below means the inventory's material controls, states, effects, and native equivalent are present in source. It does **not** mean physical-iPhone verification was possible. Terminal rows explicitly call out that distinction. “Partial” means a real user path exists but one or more material contract clauses are absent. For a missing feature, evidence points to the nearest owning surface or lower-level foundation whose public UI stops short of the capability; repository-wide searches were also used to confirm absence.

The three `Not applicable on phone` rows have source-verified native navigation equivalents; desktop-only rows without a shipped equivalent remain `Partial` or `Not built`.

## Top risks for device testing

1. **R-1 — terminal secure-context viability can invalidate the flagship loop.** The worker is loaded in a WebView with a synthetic `https://spawn.local/` base and uses WebCrypto/WebRTC from an inline document (`mobile/src/terminal/worker/worker-html.ts:4`). Static inspection and unit tests cannot establish that iOS WKWebView treats this document as a sufficiently secure context, permits the required crypto/RTC primitives, and completes identity-bound signalling in Expo Go. Test login → workspace → session first; do not spend the first device session on visual polish.
2. **The default server origin is unusable from a physical iPhone.** Neither `expo.extra.apiUrl` nor an in-app server setting is present, so the compiled fallback is `http://localhost:8000` (`mobile/src/data/api/config.ts:6`). The owner must edit config or have a previously persisted override before Login can reach spawn; this is deterministic, not a device-only uncertainty.
3. **Global workspace confirmations are unmounted.** `confirm()` returns a Promise serviced only by `ConfirmHost` (`mobile/src/components/ui/confirm.tsx:48`), but the provider/root tree never renders that host. Archive-with-live-sessions and workspace deletion appear to do nothing after the first press because the awaited Promise never settles.
4. **The root shell and deep-link/provider graph were integrated last.** Source composition and iOS export pass, but runtime route groups, splash/font readiness, notification response routing, auth redirects, or gesture/safe-area provider order can still fail during cold start (`mobile/src/app/_layout.tsx:1`). Exercise signed-out cold start, signed-in restore, workspace link, and terminal notification link.
5. **Every visible Connect Host button targets a missing route.** In-app controls push `/(onboarding)/host`, while only `/(onboarding)/device` exists (`mobile/src/components/hosts/host-list-screen.tsx:102`). First onboarding can pair; adding the next host from Hosts/Settings cannot.
6. **Skip Host is a navigation dead end.** Onboarding persists Skip and shows completion, but AuthGate routes every zero-host account back to onboarding without reading that value (`mobile/src/lib/auth-gate.tsx:31`). Test it explicitly; the user cannot reach Workspaces after choosing the offered action.
7. **Pending agent launches have no production consumer.** The launcher stores the command and creates a shell, but `deliverPendingLaunch` is only defined/tested (`mobile/src/data/queries/launcher.ts:118`). The first “launch Claude/Codex” attempt is likely to open an ordinary shell.
8. **Host-control transport is too narrow for shipped Files UI.** It supports unary requests but not capabilities or streams (`mobile/src/terminal/transport/types.ts:150`). Preview/download/upload/transfer behavior can be disabled, hang, or fail differently across daemon versions; validate folder listing/mkdir/rename/delete separately from byte transfer.
9. **Network-change recovery has no production reachability source.** Lifecycle code accepts an injected `NetworkSource`, but the app does not provide a native network adapter (`mobile/src/data/realtime/provider.tsx:62`). Wi-Fi↔cellular changes may not proactively tear down/refetch/reopen until another lifecycle or socket event occurs.
10. **Terminal touch/keyboard/selection is code-complete but empirically unknown.** WKWebView focus, iOS keyboard insets, scroll-follow, selection handles, long-press and modifier commands are precisely the behavior unit tests cannot prove (`mobile/src/terminal/TerminalSurface.tsx:206`). Separately, connection overlay timing can flash and upload progress drives JS-thread layout without a Reduce Motion guard.
11. **Device trust has a hard Expo Go ceiling.** Ed25519 registration/pinning/endorsement is implemented, but passkey PRF backup is intentionally unavailable (`mobile/src/data/trust/endorsement.ts:35`). A fresh phone needs a direct host pairing or another trusted device; verify both, plus revoke/re-pair recovery.
12. **Notifications can disagree with Settings.** The panel and presenter maintain separate in-memory stores over the same persistence key. Toggle an event/channel and trigger an alert without restarting; current code may use stale presenter preferences.
13. **No global registration-health banner warns before terminal failure.** Registration failures are visible only after opening Settings (`mobile/src/components/settings/browser-devices-panel.tsx:178`). Include a revoked/local-key-missing device in testing rather than testing only the happy path.

## Cross-cutting concerns

- **The global confirmation contract is implemented but not composed:** feature agents correctly call `confirm()`, yet P3-01's provider/root tree omits `ConfirmHost`. This is a cross-agent integration failure that specifically breaks workspace lifecycle actions while local `<Confirm>` users continue to work.
- **A complete About screen is dead code:** P3-02 built install commands, threat-model copy and public links, but no agent owned/added an About route or Settings row. P3-01 maps `/download` and `/security` deep links to Settings query parameters that P2-08's Settings screen never reads.
- **Pairing route names contradict:** P2 Hosts/Settings use `/(onboarding)/host`; P2 onboarding and P3 linking implement `/(onboarding)/device`. First-host onboarding works, but the reusable post-onboarding entry does not.
- **Server configuration has an API but no surface:** `getBaseUrl`/`setBaseUrl` and persistence exist, yet Settings exposes neither. The checked-in app always begins at localhost unless the owner edits Expo config, despite physical-iPhone operation being the campaign goal.
- **Onboarding and AuthGate disagree on “done”:** onboarding's step machine accepts a persisted host skip, while AuthGate's independent resolver considers only host count. The duplicate routing logic encodes contradictory terminal states for the same account.
- **Frozen transport drift:** `HostTransport` does not fulfill the campaign's own F-116 contract. The worker decodes hello/response frames but does not expose advertised capabilities or stream frames to feature code. P2-07 consequently added optional-method probes and disabled byte operations rather than a functioning shared interface.
- **Layout-model loss:** API/domain decoding strips unknown `LayoutV3` fields before the preserving codec sees them. A phone write can therefore erase forward-compatible desktop layout information even though the layout codec itself preserves unknown fields.
- **Two notification preference authorities:** P2-08 and P2-09 independently cache the same AsyncStorage record. They agree on serialization but not live subscription, so the UI and delivery planner can diverge inside one process.
- **Agent launch split-brain:** launcher persistence/delivery is in the query layer, while terminal readiness is owned by the overlay/worker. No integration boundary calls the one-shot delivery function or clears it after confirmed write.
- **Workspace continuity is local component state:** centralized Query data does not include a persisted current workspace/tab preference, so AuthGate and Workspace Detail cannot implement the inventory's restore semantics.
- **Trust entry is duplicated:** onboarding and Settings both register the current phone under different default labels (`spawn on iPhone` versus `iPhone`) and expose endorsements with different refresh behavior. Registration is key-idempotent, but labels and user expectations can drift.
- **Capability-disabled versus broken is inconsistent:** Files often disables an operation based on absent optional transport methods, while other live metrics make arbitrary unary requests without capability preflight. Mixed daemon versions will present contradictory availability.
- **Accepted Expo Go limitations are surfaced unevenly:** OAuth, push and passkey PRF show explicit reasons, which is good; unavailable stream transfer, ownership and secure-context uncertainty do not have equally clear user-facing capability states.
- **Accessibility is component-local, not end-to-end:** primitives provide good labels/touch targets/reduced motion, but no campaign-wide Dynamic Type/contrast/focus/hardware-keyboard test demonstrates that composed screens retain those properties.
- **Green gates are broad, not comprehensive:** the suite is deterministic and offline, but measured branch/function coverage is roughly 51%/50%. The passing 963 tests do not contradict the unwired/dead-code findings above because most integration boundaries are not behaviorally traversed.
- **List performance contracts are inconsistent:** the flagship lists use FlashList, but Hosts/Archived still use FlatList and Admin/settings collections render remote-sized arrays with `.map`; several renderers and row closures are recreated on parent state changes. Workspace Detail also subscribes to the entire session-transport record, so one session update can rerender all panes.
- **Public-surface parity is intentionally compressed and incompletely wired:** a compact About component is the correct native strategy, but dead code preserves no destination. This audit does not count an unmounted component or an ignored route parameter as a shipped capability.

## What I would build next

1. Prove R-1 on a physical iPhone, then fix the secure-context/worker loading strategy before any other feature if PTY connection fails.
2. Expose/require a usable server origin before Login, mount `ConfirmHost`, correct Connect Host route names, and route the completed About/Admin entries. These are small deterministic integration fixes with outsized first-run impact.
3. Extend the frozen host-control interface end to end with advertised capabilities, structured errors, bounded streams, cancel/timeouts, and tests; use it to make Files preview/download/upload/transfer real.
4. Wire pending agent-command delivery to terminal `ready`, with exactly-once clearing and reconnect tests.
5. Add shared-terminal ownership/Take control, because silent multi-client writes are a correctness and trust problem, not a polish item.
6. Add a warm terminal pool or another explicit keepalive ownership model so workspace↔terminal navigation does not repeatedly rebuild live sessions.
7. Complete the phone session Files route, clipboard images, multi-file upload progress/cancel/retry, and selection/bracketed-paste behavior.
8. Finish workspace semantics: persisted last workspace/tab, first-workspace onboarding, reorder, tab duplicate/home, workspace menu, Files launcher and agent/files mode switching.
9. Add a real production network-change source and consolidate notification preferences into one observable store.
10. Implement hardware-keyboard navigation/arbitration and run Dynamic Type, VoiceOver, Reduce Motion/Transparency and contrast passes on composed screens.
