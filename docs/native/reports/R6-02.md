# R6-02 — Pane rows: full width, transparent, no file path

## What I built

- Removed the pane list's horizontal item gutter so terminal, files, and unavailable rows run edge to edge on the shared `ListRow shape="fullBleed"` geometry.
- Kept the empty state and the **Add terminal or files** footer control inset with the canonical screen gutter; only list-row geometry changed.
- Kept the shared `ListSeparator` as `FlashList.ItemSeparatorComponent`, with regression coverage proving one separator is rendered between two rows.
- Overrode the terminal/files `SwipeableRow` content surface to transparent so the parent workspace-tab surface shows through at rest. The global `ListRow` still supplies the themed pressed highlight.
- Removed `session.cwd` from terminal subtitles. They now contain agent and host only, such as `Codex · office-mac`, with the agent-only fallback preserved when no host name is available.
- Removed the full path from files subtitles. They now show the host only; when no host is available the optional subtitle is omitted.
- Moved populated and unavailable pane variants from the tall row height to the shared regular row height and recentered populated-row ellipsis targets against that geometry.
- Extracted the two pane variants' identical action, frame, status, and transparent swipe geometry into one workspace-detail style module.

The `impeccable` guidance reinforced a restrained, utilitarian pass: the owner-specified hierarchy and established global primitives determined the result, with no new local row component, colour, radius, or size token.

## Deviations and why

- The files path remains available to `onOpenFiles` and still supplies the leaf in the existing title (`Files — dev`). The product request specifically removes the path from subtitle composition; removing it from routing would break pane opening.
- The shared `ListRow` currently caps all subtitles at two lines and does not expose a consumer clamp. R6-02 shortens the content to its intended single-line form and uses regular height, but did not add an unowned primitive prop.
- `.impeccable.md` was not created because it is outside R6-02 ownership. The mandated round briefs and prior native reports provide the applicable product context, and this pass introduces no new design direction.
- No simulator, Expo Go, screenshot, or manual testing was performed, per the round rules.

## Requests for other agents

- Shared `ListRow` owner: consider an optional, default-preserving subtitle line-limit prop so pane rows can explicitly clamp to one line. The current global primitive hard-codes two lines; R6-02 correctly stayed within its owned paths.
