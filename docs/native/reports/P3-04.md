# P3-04 — Test, lint and typecheck hardening

## Outcome

The complete `mobile/` tree is green and has a reproducible, fail-fast iOS CI gate. I added typed
shared test infrastructure, enforced offline Jest execution, measured coverage, found and fixed
order-dependent tests with seeded shuffles, and verified an Expo iOS export without launching the
app or a simulator.

The technical-audit framing influenced this pass by prioritising deterministic isolation, explicit
P1/P2 flake remediation, seeded repeatability, and an offline-by-default test environment. No
product behaviour changed.

## What I built

### Shared fixtures and fakes

- `tests/factories.ts`: fresh typed factories for workspace, tab, session, host, and agent domain
  shapes. Defaults form a coherent graph and accept partial overrides.
- `tests/fake-api.ts`: method/path-routed `fetch` double with request capture, async handlers,
  response helpers, global installation/restore, and fail-closed unmatched requests.
- `tests/fake-socket.ts`: controllable WebSocket lifecycle, captured sends/closes, injected-use
  support, and an idempotently restorable global installer.
- `tests/fake-transport.ts`: `SessionTransport` implementation with call recording, typed event
  controls, and controllable upload progress/completion/failure.
- `tests/render.tsx`: isolated QueryClient plus spawn `ThemeProvider`, with retries disabled and
  infinite test GC to avoid timer leakage.
- `tests/README.md`: direct-import guidance and cleanup rules for all shared support.
- Five suites / nine tests directly verify the shared support.

### Isolation and determinism

- Unmocked `fetch` and WebSocket construction now fail immediately from `tests/setup.ts`.
- Real timers are restored after every test, including after failed assertions.
- Static inspection confirmed that every test URL is handled by a fake and every imported Expo
  device API is mocked either globally or in its owning suite.
- No test needs a device, network, running server, real terminal, or simulator.

### Reproducible CI

`scripts/mobile-ci.sh` is executable, location-independent, uses `set -euo pipefail`, and runs:

1. `npm run typecheck`
2. `npm run lint`
3. `npm test -- --ci --runInBand`
4. `EXPO_NO_TELEMETRY=1 npx expo export --platform ios`

## Changes inside other agents' files

All cross-owner changes were limited to broken/flaky tests, as authorised by the quality plan:

- `mobile/src/components/ui/__tests__/overlays.test.tsx`: established a resolved-false
  `AccessibilityInfo.isReduceMotionEnabled` default before every test. The reduced-motion test had
  restored the Expo preset mock to a function returning `undefined`, so later shuffled tests tried
  to call `.then` on `undefined`.
- `mobile/src/terminal/__tests__/TerminalSurface.test.tsx`: installed removable default AppState
  and Keyboard subscriptions before every test. Restoring one case's spy previously left later
  shuffled renders with an undefined subscription handle.
- `mobile/src/lib/__tests__/providers.test.tsx`: awaited React Native Testing Library's asynchronous
  `render`; the immediate order assertion could run before providers mounted.
- `mobile/src/lib/__tests__/app-shell.test.tsx`: mocked `expo-font` and `expo-notifications`, and
  awaited `render`. This avoids Jest resolving `expo-font`'s nested `expo-asset` dependency, avoids
  loading a device-facing notification module, and matches RNTL 14's async API.
- `mobile/src/data/queries/__tests__/auth.test.tsx`: unmounted the mutation hook before clearing its
  QueryClient, eliminating a deferred React update outside `act`.
- `mobile/src/components/admin/__tests__/admin-queries.test.tsx`: unmounted all mutation hooks
  before clearing their QueryClient for the same reason.

No production source file was edited.

## Deviations from the plan

- Existing healthy feature-specific fixture modules were not rewritten to import the new shared
  factories. Their duplication was identified, but path ownership permits cross-owner edits only
  for broken/flaky/type/lint failures. New and changed suites can adopt the shared direct imports;
  rewriting passing suites would have violated the campaign's ownership rule.
- No coverage floor was added, exactly as allowed by the plan's “only if comfortably met” rule.
- The CI test step is explicitly in-band. This is slower but stable on constrained CI machines and
  preserves fail-fast behavior before the Expo export.
- No manual, simulator, Expo Go, network, or device testing was performed, per campaign rules.

## Requests for other agents

- No blocking change is required from another agent.
- For new suites, prefer the direct helpers documented in `mobile/tests/README.md`; keep
  feature-specific fakes only when the shared contract does not fit.

## Known gaps

- Whole-tree branch/function coverage is only about 50%; the green gate proves existing behavior,
  not comprehensive path coverage.
- Some older suites retain domain-specific factories and small local WebSocket/transport doubles.
  They remain valid and deterministic, but are candidates for gradual consolidation when their
  owning feature is next edited.
- Physical-iPhone and Expo Go boot behavior remains outside this assignment and was intentionally
  not exercised.
