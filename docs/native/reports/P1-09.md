# P1-09 — Terminal core implementation report

## What I built

Implemented the Expo Go terminal backend and native surface under `mobile/src/terminal/`:

- A self-contained, offline xterm.js 5.5.0 worker document containing Fit 0.11.0, Unicode11
  0.9.0, WebLinks 0.12.0, Clipboard 0.2.0, Serialize 0.14.0, and WebGL 0.19.0.
- One visible session worker with xterm and WebRTC co-located. PTY output goes directly from
  `spawn.pty` into xterm and never crosses the React Native bridge.
- One hidden host worker per mounted `HostTransportSurface`, using `spawn.host.ctl` for typed
  request/response operations.
- Signed revision-2 signalling delegated to P1-06 and WebSocket signalling relayed through P1-08.
  The browser private key never enters worker JavaScript.
- Strict `spawn.ctl` v1 JSON and 28-byte SPCT codecs; offset-anchored replay; five readiness gates;
  bounded input, output, history, request, and upload queues; reconnection and app-background
  retirement.
- Native WebView surfaces with runtime theme/font updates, native clipboard writes, denied
  background clipboard reads, terminal-owned vertical scrolling, keyboard-transition fit deferral,
  WebContent process reload, and an imperative surface handle.
- Session uploads with strict metadata checks, 20 MiB/four-active limits, 48 KiB chunks, stable UUID
  resume, three pre-effect start attempts, SCTP high/low-water backpressure, durable pre-final hook,
  and terminal `outcome_unknown` handling.
- Exhaustive key encoding and pure reducers/codecs with 125 owned test cases.

## Worker regeneration

From `mobile/`:

```sh
node src/terminal/worker/build-worker.mjs
```

The script reads the exact already-vendored xterm 5.5 package family from `web/node_modules`,
inlines all JavaScript and CSS, and rewrites both generated outputs. The final worker is 669,425
bytes and contains no remote script, stylesheet, font, or analytics reference. Runtime does not run
the generator or read outside `mobile/`.

## DataChannel contract

Every production channel is created with exactly:

```js
Object.freeze({ ordered: true })
```

No `maxPacketLifeTime`, `maxRetransmits`, negotiation override, or partial-reliability field is
present.

| Mode | Label | Protocol | Payload |
|---|---|---:|---|
| Session | `spawn.pty` | 2 | Raw binary in both directions |
| Session | `spawn.ctl` | 1 | Bounded JSON text plus 28-byte SPCT binary frames |
| Host | `spawn.host.ctl` | 1 | Bounded JSON request/response control |

Session readiness requires `bindingAccepted`, `ptyOpen`, `ctlOpen`, `daemonReady`, and
`historyReady`. Pending stdin is capped at 64 KiB and flushes only after all five. Every later write
is split at 64 KiB. PTY and control message decoding use promise tails so Blob conversion cannot
reorder messages.

The internal xterm write pump waits for each xterm completion callback, batches for at most 8 ms or
32 KiB, and caps queued output at 4 MiB. Overflow requests authoritative replay rather than dropping
a partial VT stream. Initial live output is bounded at 12 MiB, and replay waits if its explicit
`pty_offset` is ahead of locally received PTY bytes.

| F1–F4 | `1B 4F 50` through `1B 4F 53` | same |
| F5 | `1B 5B 31 35 7E` | same |
| F6–F10 | `1B 5B 31 37 7E`, `...31 38...`, `...31 39...`, `...32 30...`, `...32 31...` | same |

Ctrl applies uppercase ASCII `& 0x1f`; Ctrl-Space/Ctrl-@ is NUL; Ctrl-`?` is DEL. Alt prefixes
exactly one Escape after Ctrl conversion. Cursor/Home/End modifiers use CSI parameter
`1 + Shift + 2×Alt + 4×Ctrl`, producing parameters 2 through 8. Literal `| / - ~ \`, empty input,
and committed Unicode pass through unchanged. Tests assert the actual encoded hex for all named
keys, Ctrl-A through Ctrl-Z, punctuation edges, cursor modifiers, symbols, and Unicode.

## Capability probe and physical-device check

The worker records and emits a typed diagnostic containing:

- `globalThis.isSecureContext === true`;
- whether `RTCPeerConnection` is constructible;
- whether `createDataChannel` succeeds;
- whether an ordered DataChannel opens across a local offer/answer loopback pair within two seconds;
- active renderer (`webgl`, `dom`, or `null`) and failure detail.

The probe runs at boot and caches/re-emits its completed result after `init`, so an early WKWebView
message cannot be lost before native listeners attach. Any required capability failure moves the
transport to `failed` with a typed error instead of hanging.

The primary source is inline HTML with `baseUrl: "https://spawn.local/"`. A one-line switch in both
surfaces selects the bundled HTML file fallback via React Native's asset resolver. If both origins
fail on a future WebKit, the documented unimplemented third option is to serve the same immutable
worker from the spawn HTTPS origin.

On the first physical iPhone run, inspect the diagnostic before testing a session. All four booleans
must be true; renderer may be WebGL or DOM. Then verify direct and forced-TURN connections, a sustained
output flood, background/foreground retirement, WebContent-process reload, soft-keyboard fit, IME,
selection/clipboard, and scroll-away behavior. If only `isSecureContext` fails, flip the file-worker
switch and repeat before investigating signalling.

## Research corrections and implementation deviations

- R04's WebView option permits the worker to own the authenticated WebSocket and signing codec.
  Frozen architecture D3 supersedes that option: signalling remains in RN and only bounded sign
  transcripts/signatures cross the bridge. No private key or bearer token enters the worker.
- R09 TL;DR 9 describes RN-to-WebView output batching because that report scoped rendering after a
  separate transport supplied bytes. D3 supersedes that boundary: the same 8 ms / 32 KiB / one-write
  / 4 MiB policy runs entirely inside the worker; PTY output never crosses RN.
- R04/R09 package tables target Expo SDK 57. The actual frozen scaffold is SDK 54 with
  `react-native-webview` 13.15.0, keyboard-controller 1.18.5, and Expo Clipboard 8.0.8. The code uses
  the installed versions and did not change dependencies.
- R09 lists `expo-asset` for the file fallback, but it is absent from the frozen SDK-54 dependency
  set. The fallback uses `Image.resolveAssetSource` for the Metro-bundled `.html` asset; Metro's
  configured asset extensions include `html`.
- The frozen dependencies do not contain `@xterm/addon-search`. Native search is implemented as a
  deliberate buffer scan using xterm's proposed buffer API, while Serialize remains loaded only as
  an internal recovery hook.
- No protocol-value contradiction was found in R04's DataChannel, SPCT, readiness, replay, input,
  or upload contracts. I consulted the web upload hook only because R11 specified three start
  attempts but did not state its timeout; the source confirms 5 seconds per attempt.

## Known gaps

- Secure-context treatment of inline `baseUrl`, the bundled-file origin, loopback WebRTC, WebGL, TURN,
  SCTP backpressure events, and WebContent lifecycle are implemented but cannot be certified without
  the owner's physical iPhone and its exact Expo Go/WKWebView build.
- iPhone performance targets (60 fps and sustained 1 MiB/s), IME/dictation, external keyboards,
  VoiceOver interaction, clipboard gesture behavior, and touch-scroll ownership remain device gates.
- Durable upload storage itself belongs to the centralized data/UI layer. This implementation enforces
  the pre-final durability callback and stable-ID reconciliation semantics but does not choose or own
  the eight-slot persistent journal.
- The file-origin fallback is compiled behind a one-line switch but remains unexercised. The primary
  inline HTTPS-base strategy is intentionally the default until the device probe says otherwise.
