# P0-01 — Expo SDK 54 scaffold and theme system

## What I built

Created the complete `mobile/` Expo SDK 54 foundation for the native campaign:

- Expo Router app entry and a minimal themed `spawn` placeholder screen.
- Expo, EAS, TypeScript, Metro, Babel, Biome, Jest, and npm configuration.
- An isolated Metro setup that resolves nested packages inside `mobile/node_modules` while blocking
  `web/`, `server/`, `daemon/`, and the repository-level `node_modules` tree.
- The complete shared directory skeleton, with `.gitkeep` files only where a later owner will add
  implementation.
- Solid brand-palette placeholder icon, adaptive icon, and splash assets, each 1024×1024 PNG.
- The full native token transcription: semantic palettes, terminal ANSI palettes, typography,
  spacing, radii, chrome geometry, effects, motion/easing, assembled themes, persistence provider,
  and the public `@/theme` barrel.
- A Jest/React Native test harness with Reanimated, Gesture Handler, Haptics, SecureStore, and
  AsyncStorage setup.
- Seven byte-identical protocol/layout fixtures copied from `proto/` for later offline vector tests.

## Public `@/theme` API

The frozen core contract is implemented as:

```ts
export type ThemeMode = "light" | "dark" | "system";
export type ThemePreference = ThemeMode;
export type ResolvedTheme = "light" | "dark";

export interface Theme {
  isDark: boolean;
  colors: Colors;
  space: (units: number) => number;
  radii: { sm: 6; md: 8; lg: 10; xl: 12; xxl: 16; pill: 9999 };
  type: Typography;
  motion: Motion;
  terminal: TerminalTheme;
}

export function ThemeProvider(props: React.PropsWithChildren): React.JSX.Element;
export function useTheme(): Theme;
export function useThemeMode(): {
  mode: ThemeMode;
  setMode: (mode: ThemeMode) => void;
};
export function resolveTheme(
  mode: ThemeMode,
  osScheme: "light" | "dark" | null | undefined,
): ResolvedTheme;
export function themeForMode(mode: ResolvedTheme): Theme;
export function isThemeMode(value: unknown): value is ThemeMode;
export const isThemePreference: typeof isThemeMode;
export const THEME_STORAGE_KEY: "spawn.theme";
export const lightTheme: Theme;
export const darkTheme: Theme;
export const themes: Record<ResolvedTheme, Colors>;
```

The barrel also re-exports the complete token surface:

- Colors: `Colors`, `ThemeColors`, `lightColors`, `darkColors`, `pressroomColors`,
  `grimoireColors`, `tabSurfaces`.
- Typography: `Typography`, `fontFamily`, `fontWeight`, `fontSize`, `lineHeight`,
  `displayLineHeightRatio`, `letterSpacing`, `typeStyles`, `displayClamp`, `clampDisplay`,
  `typography`.
- Spacing/layout: `space`, `spacing`, `radii`, `radius`, `specialSpace`, `borderWidth`, `chrome`.
- Effects: `shadow`, `blurRadius`, `opacity`, `alpha`, `layer`.
- Motion: `Motion`, `duration`, `easingCurve`, Reanimated-compatible `easing`, `transition`,
  `gesture`, `transform`, `pattern`, `repeat`, `motion`.
- Terminal: `TerminalTheme`, `TerminalPalette`, `terminalMetrics`, `terminalDark`,
  `terminalLight`, `terminalLightSelectionSources`, `terminalPalette`.

`ThemeProvider` starts in `system`, follows `useColorScheme()` live, validates stored values, and
persists explicit choices through AsyncStorage at `spawn.theme`.

## Deviations and research corrections

1. `research/08 §13` declared Bun and Bun-based scripts. The assignment explicitly required npm,
   no `packageManager`, and the exact npm scripts, so the scaffold follows the assignment.
2. The research EAS profile set `developmentClient: false`; the assignment explicitly required
   `true` for the eventual development build. `expo-dev-client` remains intentionally absent for
   the Expo Go campaign.
3. Router 6's Radix dependencies made npm auto-select `react-dom@19.2.8`, which conflicts with SDK
   54's React 19.1. Expo's compatible `react-dom@19.1.0` and `react-native-web@^0.21.0` were added
   directly; the resolved web package is 0.21.2. Both are pure JS and do not change Expo Go's native
   binary.
4. `test-renderer@1.2.0` depends on React Reconciler 0.33 (React 19.2). It was corrected to
   `test-renderer@1.1.0`, which uses React Reconciler 0.32 for React 19.1 and satisfies RNTL 14's
   `test-renderer@^1.0.0` peer.
5. The isolated Metro config could not resolve Router's nested `@expo/metro-runtime`; SDK 54's
   6.1.2 pin was added directly.
6. The research Metro config's `disableHierarchicalLookup: true` also hid legitimate nested
   dependencies such as React Native's `@react-native/virtualized-lists@0.81.5`. Hierarchical lookup
   is therefore enabled inside `mobile`, while an explicit block list prevents resolution from the
   repository's parent `node_modules` and sibling product trees.
7. The initial graph contained `@react-navigation/native` 7.1.8 at root and 7.3.17 under Router.
   npm deduplication selected one 7.3.17 copy within Expo's declared `^7.1.8` compatibility range;
   Expo Doctor's duplicate-native-module check then passed.
8. Expo install added the first-party `expo-font` and `expo-sqlite` config-plugin entries. Both are
   SDK 54/Expo Go modules; they do not introduce a custom native module.
9. Biome 2.5.10 deprecates `rules.recommended`; the config uses the equivalent
   `rules.preset: "recommended"`. Golden fixtures are excluded from formatting so they remain
   byte-identical.
10. The plan's `splash.png` filename is used instead of the research sample's `splash-icon.png`.
11. `effects.ts` is included because the closing native-token specification contains those tokens,
   even though the shorter work-item file list omitted the module. It does not add a field to the
   frozen `Theme` interface.

## Known gaps

- No simulator, app launch, screenshot, or physical-device check was performed, per campaign rule.
  The headless iOS bundle is the automated proof available in Phase 0.
- Images are deliberate solid-color placeholders and fonts use system fallbacks. P3-01 owns final
  branding, app-shell replacement, and font bundling.
- `eas init` has not supplied an EAS project ID, update URL, or runtime policy.
- The `development` EAS profile is prepared with `developmentClient: true`, but this Expo Go phase
  intentionally does not install `expo-dev-client`; do not use that profile until the campaign
  explicitly moves to development builds.
- The machine has Node 24.18.0, not the configured Node 22.19.x baseline. npm emitted engine
  warnings, but TypeScript, Jest, Expo export, Expo install validation, and Expo Doctor all passed.
  CI/EAS remain pinned to Node 22.19.0.
- `npm audit --omit=dev` reports 68 transitive advisories (16 moderate, 52 high, 0 critical),
  primarily through the SDK-locked Expo/React Native/Metro graph. No forced audit upgrade was
  attempted because it would break Expo Go 54 compatibility; re-audit during the post-Expo-Go SDK
  upgrade.
