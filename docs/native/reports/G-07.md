# G-07 — Close the unwired lifecycle holes

## What I built

Closed the three lifecycle seams identified by `research3/19`:

1. Session and host signalling channels now register their live generation with the shared realtime lifecycle registry before connecting. Background/interface retirement closes that generation, recovery opens a fresh one, and terminal channel close unregisters the lease so a dead surface cannot reopen later.
2. Explicit credential clearing and implicit token expiry now use one removal transition. That transition clears the pending authenticated deep link before deleting persistence and notifying token subscribers.
3. Token expiry now notifies subscribers exactly once. A second read of the already-cleared token neither deletes nor notifies again.

Added explicit production-wiring regressions covering both signalling channel types, both lifecycle retirement reasons, unregister-on-close, stale authenticated-link removal, and one-shot expiry notification.

## Observable symptoms before the fix

- **Realtime registration:** `retireRegisteredGenerations()` and `reopenRegisteredGenerations()` ran at lifecycle boundaries, but no production signalling channel registered. The ordered transport recovery stage was therefore empty, so a visible channel retired by a network transition had no registry-owned path to a fresh generation.
- **Pending authenticated link:** a link remembered while signed out survived credential clearing. A later sign-in, including a different account, could consume and navigate to that stale account-scoped intent.
- **Token expiry:** `authToken.get()` deleted an expired record directly and returned `null` without notifying subscribers. `AuthGate` could keep its prior authenticated state until an unrelated render or navigation caused another bootstrap read.
