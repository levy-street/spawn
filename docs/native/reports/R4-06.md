# R4-06 Report — Onboarding and pairing

## What I built

- Made both onboarding route scenes own a global `Screen` and exactly one global `AppHeader`.
- Added the required `Connect a host` header to standalone pairing and a `Set up Spawn` header to the full onboarding flow.
- Painted both scene roots with `theme.colors.background`, leaving the header as the sole owner of the top safe-area inset.
- Added shared back navigation that pops when possible and falls back to `router.replace("/hosts")` for a directly opened route.
- Reduced the onboarding route modules to thin component exports, so the header and content move together with the native card gesture.
- Replaced local bordered content wells with flat global `Card` surfaces and rebuilt pairing trust failures on the global `EmptyState`.
- Added render coverage for the singular header, themed ground, stack-pop behavior, and Hosts fallback.

The `impeccable` guidance kept this pass restrained: it preserved the existing product hierarchy and moved visual decisions into the established global primitives instead of introducing new styling.
