# F-02 — Terminal containment and full-surface dismissal

## What I built

### WebView containment

- Changed both the terminal and hidden host worker WebViews to `originWhitelist={["*"]}` so React
  Native WebView never sends a rejected origin directly to the operating-system opener.
- Added one shared, strict bootstrap policy. It permits only `https://spawn.local/`, `about:blank`,
  or the exact configured file-worker URI when that fallback is enabled. External URLs, arbitrary
  paths on the synthetic origin, and unrelated file URLs are rejected in-app.
- Added `onOpenWindow`, explicitly disabled automatic JavaScript windows, and retained disabled
  link previews and multiple-window support. The hidden host worker drops new-window requests.
- The visible terminal forwards new-window targets through its existing `onLink` bridge callback.
  `TerminalOverlay` validates `http:`, `https:`, or `mailto:` and then deliberately calls
  `expo-linking`'s `Linking.openURL`; unsupported schemes remain in-app and show the existing notice.
- Confirmed the authored xterm WebLinks addon posts `{ type: "link" }` through the native bridge.

### Full-surface terminal dismissal

- Added a rightward `FullSurfaceDismiss` recognizer around the entire terminal overlay content while
  retaining the shared overlay's existing header-only downward drag as an additional affordance.
- The parent RNGH pan uses manual activation. It observes all starting positions, activates only
  after horizontal-right intent wins the axis lock, and fails leftward or sufficiently vertical
  movement before activation. `cancelsTouchesInView(false)` and no simultaneous scroll composition
  let taps and terminal-owned vertical scrollback continue to the child WebView.
- The gesture rubber-bands visually and reuses the shared `shouldCommitDrag` and `restingOffset`
  functions for the 22% velocity-projected commit. It springs back or off-screen and respects the
  reduced-motion preference.
- `haptics.overlayDismiss()` fires when the projected threshold is crossed during `onUpdate`, with
  a per-gesture gate that prevents duplicate feedback.

  the existing worker contract explicitly asserts that sentinel. The WebView `source.baseUrl` is
  still the effective bootstrap base, and the strict native callback remains the containment policy.
- The three repository-wide verification commands are not globally green because parallel-agent
  files are mid-migration. Per the assignment, I did not edit those files; F-02-scoped verification

## Known gaps

- Research 14 explicitly marks parent-RNGH recognition above WKWebView as a physical-device unknown.
  The implementation uses the recommended manual-activation parent detector, but an iPhone must
  confirm that horizontal touches from every terminal cell reach it. If WKWebView prevents that,
  the documented fallback is one native-stack full-screen horizontal gesture with the nested Modal
  removed; both recognizers must not be enabled together.
- Physical-device confirmation that the initial inline worker remains in-app is still required by
  the campaign's human verification phase.
- The file-worker fallback remains disabled, so its exact-URI allowlist is unit-tested but not
  exercised at runtime.
