# R4-08 — Terminal overlay standardisation

## What I built

- Replaced the terminal's native-stack header configuration with the frozen global `AppHeader`.
  It now owns the safe-area inset, standard back chevron, centred session title/subtitle, connection
  badge, and the terminal action-menu declaration.
- Moved rename out of the old custom native-header title row and into the shared `Dialog`, `Input`,
  and `Button` primitives. All existing terminal actions remain in `NativePopover`, including the
  destructive kill action.
- Kept the connection badge vertically centred in header usage so `Failed` no longer inherits the
  badge primitive's body-copy `flex-start` alignment.
- Explicitly disabled the terminal route's native header and retained one native full-screen
  horizontal back recognizer. No `gestureResponseDistance` is set, so recognition is not limited
  to the left edge. Loading, unavailable, and connected states all use the same route options.
- Rendered loading/unavailable `AppHeader`s inside `Screen.header`, and kept the connected
  `TerminalHeader` inside the terminal route scene. The native scene transform therefore carries
  the header and body together during the swipe-back drag.
- Kept the live terminal free of a competing nested page-dismiss recognizer. The existing
  `FullSurfaceDismiss` test now directly covers a pan beginning at screen centre, while route tests
  cover the production native-stack recognizer and its unrestricted activation region.
- Replaced generic terminal chrome pressables with shared buttons: modifier keycaps, keyboard
  dismiss, the extra-key sheet, selection actions, and jump-to-latest. Overlay surfaces remain
  solid `theme.colors.popover` views with themed hairlines.
- Audited `SwipeDismissOverlay`: its default activation region is already `"full"`, and its
  `GestureDetector` wraps the same animated panel that contains all children. No source change was
  needed there.

The `impeccable` guidance reinforced a restrained, utilitarian treatment: existing theme tokens,
solid surfaces, native navigation behavior, and shared controls rather than new terminal-specific
chrome.

## Deviations and why

- I did not mount the legacy `FullSurfaceDismiss` around the live WebView. Production uses the one
  native-stack full-screen recognizer, which is above the route scene and avoids reintroducing the
  previously documented parent-RNGH/WebView competition. The historical component remains because
  it is an owned pre-existing file and its pure gesture coverage is still useful.
- `mobile/src/components/ui/swipe-dismiss-overlay.tsx` was not changed because it already wraps all
  children in the animated panel and defaults to full-surface gesture eligibility.
- `theme/sizing.ts` was not changed; all new geometry uses the frozen `sizing.appHeader` tokens.

## Requests for other agents

- **R4-01 / integration:** `TerminalHeader` supplies both `AppHeader.accessory` (connection badge)
  and `AppHeader.actions` (terminal menu), as allowed by the frozen prop interface. The current
  `AppHeader` implementation renders `accessory ?? actions`, so the accessory suppresses the menu.
  Please make the global component render both declarations without changing the frozen API, or
  provide the product-approved global composition. R4-08 cannot edit that path.

## Known gaps

- Automated tests prove route configuration, axis-lock decisions, and scene ownership. The separate
  iPhone pass still needs to confirm rightward drags from roughly 10%, 50%, and 90% of the terminal,
  plus vertical scrollback and long-press selection arbitration inside the WebView.
