# P2-05 — Terminal overlay

## What I built

Implemented the native terminal route and all user-facing terminal chrome around the Phase 1
`TerminalSurface`/`SessionTransport` boundary.

- A card-presented, full-screen `SwipeDismissOverlay` whose drag gesture is startable only from the
  header. The route disables the navigator's full-surface gesture so terminal scrollback retains
  vertical gesture ownership.
- A safe-area header with editable session name, inferred agent type/icon, host, cwd, all seven
  `TransportState` presentations, and actions for rename, restart, kill, upload, search, font size,
  copy mode, and diagnostics.
- Initial connection overlays plus non-destructive reconnect/closed/failed banners after a terminal
  has been ready, explicit retry by worker remount, ready/disconnect haptics, and no blank unexplained
  terminal state.
- Pure reader-follow state: output does not move a reader who has scrolled away, unread output expands
  the jump pill to `New`, and jump/input/manual arrival at bottom restore follow.
- A `KeyboardStickyView` modifier bar that tracks the keyboard, preserves a pinned Send control,
  offers explicit keyboard dismissal, and keeps terminal fitting frozen/coalesced during keyboard
  transitions. The Phase 1 surface independently preserves the same fit invariant internally.
- Momentary and locked Ctrl/Alt with double-tap and long-press lock, 10-second armed timeout, stateful
  accessibility labels, and clearing on blur/session change.
- Native terminal search, font-size stepper (10–20 px), copy-selection toolbar, long-press copy mode,
  clipboard paste with 64 KiB transport chunking, >100 KiB confirmation, 1 MiB cap, and progress.
- Foreground keep-awake only while the focused terminal is ready; terminal theme changes continue to
  flow through the Phase 1 surface without reconnecting.
- Session upload UI using DocumentPicker, Expo File/Crypto, the Phase 1 upload handle, exact weighted
  upload ratio, 4% minimum painted width, 420 ms hold, complete-on-settle, and 200 ms fade. The final
  dispatch callback durably reserves `outcome_unknown` in AsyncStorage before the final chunk and
  acknowledged completion clears it.
- TanStack Query data/mutation hooks for session+host loading, rename, restart, and kill cache updates.

## Modifier bar key list as shipped

Primary horizontal row, with Send pinned outside the scroller:

- Paste
- Esc
- Tab; long-press sends Shift-Tab
- Ctrl and Alt, each off/armed/locked
- Ctrl-C, Ctrl-D, Ctrl-Z, Ctrl-L, Ctrl-R
- Up, Down, Left, Right; long-press variants are Page Up, Page Down, Home, End
- `|`, `/`, `-`, `~`
- More
- Dismiss keyboard
- Send (`CR`)

The More sheet contains Home, End, Page Up, Page Down, Insert, Delete, Shift-Tab, and F1–F12.
Every byte-producing control builds a `KeySpec` and calls Phase 1's `encodeKey`; no escape sequence is
hand-written in the UI layer.

## Deviations from the plan

1. Font size uses P1-08's existing `session-ui` store exactly as available. That store is currently
   memory-only and keyed by session, while the plan asks for persisted per-user/device preference.
   I did not modify another agent's store.
2. The frozen `TerminalSurfaceHandle` has `copySelection()` but no `enterSelection`, selection-change
   event, selection rectangles, or `paste(text)` method. I implemented native long-press copy mode,
   the native toolbar, `copySelection()`, and the plan-specified chunked transport paste. Exact xterm
   cell-handle acquisition and bracketed-paste-aware `term.paste()` cannot be added without expanding
   that Phase 1 interface.
3. The plan permits pinch-to-zoom **or** a stepper. The shipped control is the simpler persisted-store
   stepper, so no pinch gesture was added.
4. No agent-logo bitmap assets or shared native agent-logo component exist in the current scaffold.
   The header therefore uses the shared Bot/Terminal icon plus the inferred agent type label.
5. No simulator, Expo Go, screenshot, or manual testing was performed, per campaign rules.
