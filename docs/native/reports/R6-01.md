# R6-01 — Persistent route shell and rounded overlays

## What I built

- Replaced the flat drawer `Stack` with Expo Router `Tabs` using the existing custom bottom bar. Tab animation is explicitly `none`, tab presses never call `push` or `replace`, and `backBehavior="none"` prevents tab taps from becoming another back history.
- Added retained native stacks at each existing route boundary. Because the public tree splits plural roots from singular detail URLs, the shell treats `workspaces` / `workspace`, `hosts` / `host` / `legion`, and `settings` / `admin` as three visible destination families and remembers the active companion tab. Hosts → host detail → Workspaces → Hosts therefore returns to that host detail and its nested stack.
- Added a shell back override for companion-tab roots (`/workspace/:id`, `/host/:id`, `/legion`, `/admin`), while deeper routes continue to pop their own native destination stack.
- Portalled one `BottomNav` through `react-native-screens`' `FullWindowOverlay`. It stays mounted at window level above pushed cards, the root Terminal card, bottom sheets, and full-screen React Native modals. A layout reservation charges only the non-safe-area nav chrome; the bar itself paints/owns the device inset, and Terminal has the same tokenized content clearance.
- On a nav tap, the bar dismisses all Gorhom sheets and every overlay registered through the new `registerNavigationOverlayDismiss` interface. Active-tab or root-overlay taps also `POP_TO_TOP` and navigate to the destination root. A tab switch with no overlay focuses the retained tab route instead.
- Removed Hosts and Settings header destinations at the global `AppHeader` boundary and in `headerDestinationActions`. `New workspace`, `Connect a host`, Legion, Admin, workspace `+`, workspace `…`, and terminal actions remain contextual screen actions. The three effective call sites cleared are `workspace-list-screen.tsx`, `host-list-screen.tsx`, and `settings-screen.tsx`.
- Corrected `AppHeader`'s trailing composition so an accessory no longer suppresses declared actions; Terminal now renders its connection accessory and ellipsis action together.
- Kept `headerDestinationActions` because Settings still uses it for the non-primary Admin destination. Legion and Admin remain reachable and are not stranded.
- Standardised native-card gestures on the installed API: React Navigation's `animationMatchesGesture`, `fullScreenGestureEnabled`, and `fullScreenGestureShadowEnabled` map to `react-native-screens`' `customAnimationOnSwipe`, `fullScreenSwipeEnabled`, and `fullScreenSwipeShadowEnabled`. Both native recognizers now use `simple_push`.
- Confirmed that installed `react-native-screens` exposes no pushed-card radius option. The shared destination stack and Terminal scene therefore use the existing `theme.radii.xxl` on `contentStyle` with clipping; `SwipeDismissOverlay` applies the same radius to its moving panel. Header/bottom insets keep settled content out of the clipped physical corners.

## Navigator approach and cost

I chose Expo Router `Tabs` with a custom tab bar and nested `Stack` layouts. A replace-based Stack shortcut was rejected because it would avoid one animation but discard each destination's retained history and make back behavior depend on whichever destination was visited last.

The cost is six new layout boundaries plus an explicit three-family route map. The existing URLs put roots and details in sibling folders, so the physical tab state has retained companion tabs hidden behind the three visible destinations. The behavior survives destination switches, but the first companion screen returns to its plural root through an instant route fallback rather than a native pop gesture. A literal one-Stack-per-destination tree would require relocating screen route files owned by R6-02/R6-03 and other screen owners.

## Overlay layering decision

The nav is deliberately above full-page modals as requested; there is no modal exception. `FullWindowOverlay` also keeps it above the root Terminal route even though Terminal is a sibling in the outer root stack. The ordinary tab-bar reservation excludes the device bottom inset so existing Screen inset ownership and the portalled nav do not create the prior double-safe-area gap.

## Deviations and why

- I did not edit the three screen call sites or their tests because they are outside R6-01 ownership. `AppHeader` is the global enforcement point, so the requested buttons are absent now without clobbering another agent's screen work.
- No radius or size token was added. `theme.radii.xxl` and the existing bottom-nav tokens are the closest established values.
- No simulator, Expo Go, screenshot, or manual test was run, per the round rules.

## Known gaps

- Full-screen `Dialog` is visually below the nav but does not yet register with the new dismiss interface. A dialog opened on a retained root can therefore remain mounted after a different-tab press until the overlay-owner request above lands.
- The nav overlays current `Dialog`/`Sheet` bottom content. Their unowned primitives need the requested nav-chrome content clearance for the last control/row to remain unobscured.
- Companion-root back uses the documented instant route fallback; only nested pushes inside those companion stacks have native swipe-back.
- The four stale out-of-scope Jest assertions keep the full command red; all R6-01-owned tests and gates pass.
- Manual iPhone validation remains for the separate verification pass.
