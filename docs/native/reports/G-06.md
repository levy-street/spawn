# G-06 — Terminal header, native menu, and dismissal from anywhere

## What I built

### Native terminal header

- Re-enabled the native-stack header for the terminal route and left `headerLeft` unset, so iOS
  supplies its normal back button and back-history behavior.
- Removed the custom close chevron, safe-area header math, and CWD/folder-path row.
- Moved the Spawn agent mark, title, host/agent subtitle, connection chip, and ellipsis into the
  native header. The mark now has the canonical 12pt cluster gap to its right.
- Put the connection chip in the same title-line flex row, rather than centering it against the old
  two-line title column. This places `Failed` on the documented optical title baseline.
- Kept inline rename behavior in the native header and retained the existing title fallback rules.

### Wide guarded-material popover

- Replaced the terminal's generic `Menu` with wave A's frozen `NativePopover` primitive. That
  primitive guarantees a 260pt minimum width, a 320pt cap, 44pt rows, and guarded
  `GlassSurface`/explicit blur fallback behavior.
- Kept all actions: Rename, Restart, Upload file, Search terminal, Font size, Copy mode,
  Diagnostics, and Kill session.
- Marked Kill session destructive and used SF Symbol names for all eight command icons. The
  header ellipsis also uses the chrome/SF Symbol path.

### One dismissal recognizer in every state

- The terminal route now sets a full-screen, horizontal, native-stack card back gesture in its own
  `Stack.Screen` options. The same options render before the loading, error, and connected branches.
- Removed `SwipeDismissOverlay` and `FullSurfaceDismiss` from connected terminal content. The live
  terminal is ordinary route content, not a loaded-state-only React Native `Modal`.
- Explicitly disabled WKWebView's own back/forward navigation gesture. Terminal scrollback and the
  existing selection long press remain inside the route, while the navigation controller owns the
  horizontal page-back gesture above the entire route.

Recognizer ordering was verified structurally and with tests: the native-stack ancestor is
configured `fullScreenGestureEnabled: true` and `gestureDirection: "horizontal"`; connected content
asserts that neither nested page-dismiss wrapper is mounted; and `TerminalSurface` asserts
`allowsBackForwardNavigationGestures={false}`. The pure horizontal axis-lock table still passes.
This is the strongest automated proof allowed by the campaign; finger-level WKWebView arbitration
still requires the later physical-iPhone acceptance pass.

The `impeccable` UI guidance influenced only interaction-quality details (clear hierarchy, native
chrome, full touch targets, restrained material use). Spawn's frozen tokens and cited research
remained authoritative; no independent visual system was introduced.

## Deviations from the plan

1. No genuine single-tap UIKit `UIMenu` was introduced. Research 16 establishes that Expo Go 54
   has no supported stable API for it. The assigned wave-A `NativePopover` is the specified
   guarded-native-material solution and retains the required anchored presentation.
2. The previous standalone `FullSurfaceDismiss` source and its regression tests remain in the
   owned directory, but it is no longer imported or mounted by terminal runtime content. Keeping
   the pure axis-lock artifacts preserves the plan's explicit pure-test requirement without
   retaining competing recognizers in the rendered hierarchy.
3. Full-tree final commands were affected by the concurrently edited G-05 workspace-detail paths.
   Per path ownership, those files were not changed. G-06-focused verification is clean.
