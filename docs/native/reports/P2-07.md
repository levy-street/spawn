# P2-07 — Files: explorer, preview, uploads and downloads

## What I built

- Added the Files tab root: it lists paired hosts, preserves the shared host ordering, communicates
  online/offline state, and opens the native per-host browser only for an online trusted host.
- Added a phone-native, current-directory `FlashList` explorer over `HostTransport` with home-root
  containment, native back navigation, breadcrumbs, host-order rows, an explicit **Load more**
  footer, pull-to-refresh, a dotfile visibility control, size/mtime metadata, and file-kind icons.
- Added host-control mutations for `fs.home`, `fs.list`, `fs.mkdir`, `fs.rename`, and `fs.remove`,
  including daemon-compatible leaf-name validation, recursive-folder delete confirmation, and the
  documented permission/root/symlink error copy.
- Ported the complete name-based preview registry and resolution order, including whole names,
  compound suffixes, extensionless documentation prefixes, executability signals, and all ten
  preview kinds.
- Enforced the 1 MiB text decode, 4 MiB automatic-load, 24 MiB ordinary inline, 128 MiB PDF, and
  512 MiB media/host-transfer ceilings before fetching.
- Ported UTF-8 partial-tail/BOM/CRLF handling, NUL binary sniffing, and 5,000-line truncation.
- Ported the bounded forward-only code scanner, split by configuration/scanner responsibility; it
  tokenizes comments, strings, numbers, keywords, punctuation, and XML markup without scanning an
  unbounded suffix.
- Added a bounded native Markdown renderer with inert raw HTML, remote-image labels, and an
  allowlist of `http:`, `https:`, and `mailto:` links.
- Added the full host-transfer pure protocol layer: 8 KiB chunks, incremental SHA-256, exact
  sequencing/length/digest validation, 512 MiB enforcement, inactivity timeout, cancellation,
  partial-sink deletion, upload pre-hash, and the post-`stream.end` `outcome_unknown` boundary.
- Added native cache-file sinks through Expo FileSystem, foreground keep-awake, byte progress,
  cancel controls, verified-file sharing, image/SVG/QuickLook rendering, local PDF WebView rendering,
  media fallback rendering, and previous/next viewer navigation.
- Session uploads were intentionally not implemented in this scope.

## Deviations from the plan

1. The current `P1-09` `HostTransport` exposes only `request()`/`cancel()`. Its worker forwards
   ordinary `host-response` frames but drops `stream.chunk`, `stream.end`, and `stream.error` frames,
   and it exposes no host write-stream sender. Consequently, listing and mutations are live, while
   preview/download/upload byte paths cannot activate against the current production transport.
   I implemented and tested the complete stream consumers, writers, local sinks, progress and
   cancellation boundary, then feature-detected a future high-level stream interface and fail
   closed in basic-control mode. I did not edit P1-09-owned files.
2. The frozen dependency set omits the research-recommended `unified`, `remark-parse`, and
   `remark-gfm`. I implemented a bounded GFM-shaped native parser for headings, fenced code,
   quotes, lists/tasks, tables, paragraphs and links. Its security posture matches the requirement,
   but complex nested GFM syntax is not full parser parity.
3. The frozen dependency set also omits `expo-sharing`, `expo-video`, and `expo-audio`. Verified
   files use React Native's native iOS share sheet, while PDF/audio/video use the installed WebView
   local-file fallback. No dependency was added.
4. The plan explicitly requires a dotfile toggle, while research/11 says the web explorer always
   shows dotfiles. The native explorer follows the plan: dotfiles are shown by default and may be
   hidden explicitly.
5. Per the phone-native recommendation, the browser is a current-directory list with breadcrumbs
   rather than the desktop explorer's deeply indented expansion tree.

## Requests for other agents

- **P1-09 / terminal transport owner:** expose verified host stream operations on `HostTransport`
  (or an agreed adjacent interface): `readFile`, ranged `readHead`, `previewImage`, and the host
  upload begin/chunk/end/cancel path. The worker bridge must forward and validate incoming stream
  chunk/end/error frames, send ACK/cancel frames with the bounded tombstone policy, and send upload
  chunks under SCTP backpressure. Preserve daemon `{code, detail}` errors instead of collapsing them
  into an untyped `Error`, so the explorer can always show the exact permission/symlink copy.
- **P3-05 / boot verification:** physically spike local `file://` PDF, audio/video WebView playback,
  and React Native `Share.share({url})` exposing iOS “Save to Files,” as the research requires.

## Known gaps

- With the current P1-09 transport, preview, download/share, and host upload are runtime-blocked;
  upload picking is therefore not surfaced. Explorer listing, paging, navigation and mutations do
  use the available live transport.
- Full nested-GFM parsing requires the omitted unified/remark packages or an approved equivalent.
- True multipage PDF and device-codec media support remain physical-iPhone risks. Viewer failures
  retain metadata and download/share fallback rather than showing an empty surface.
- React Native's share sheet is used because `expo-sharing` is absent; “Save to Files” availability
  still needs the requested device check.
- Foreground transfer primitives cancel cleanly and keep the screen awake, but no Expo Go client can
  promise continuous WebRTC progress while iOS suspends the app.
- No simulator, Expo Go launch, screenshot, network call, or manual/device test was performed, per
  campaign rules.
