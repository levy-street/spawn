# G-04 — Workspace list and new-workspace form

## What I built

- Rebuilt each workspace entity on the frozen `ListRow` primitive with `height="tall"`. The
  rendered row now has the canonical 76pt minimum height, 32pt workspace mark, 44pt trailing
  action target, and typography/spacing from `theme/sizing.ts`.
- Preserved the complete row interaction surface: open, long-press menu, rename swipe, archive or
  restore swipe, attention status, change icon, duplicate, archive/unarchive, and delete.
- Removed the workspace list's local `SafeAreaView` from loading, error, and loaded states. The
  route-owned `Screen` is now the only top-inset owner.
- Removed the duplicate in-content “Workspaces” title bar. A small native-header configurator now
  adds the existing New action beside the existing Hosts and Settings destinations, using the SF
  Symbol chrome path for the plus icon.
- Updated list/search/loading geometry to semantic phone-size tokens. Loading skeletons match the
  tall row silhouette and the list uses the standard 16pt screen gutter and 8pt row rhythm.
- Re-composed the full-mobile new-workspace form around `Screen scroll footer`. Its footer passes
  exactly two keyed children so `FooterActions` gives Cancel and Create workspace equal shares of
  the available width after the standard 12pt gap. Both use the default 48pt control size.
- Made the form footer the sole bottom-inset owner and retained the dialog's existing top inset.
  `KeyboardStickyView` now follows the keyboard while `KeyboardAwareScrollView` keeps fields
  visible.
- Preserved manual-refresh isolation: the list's `refreshing` prop is driven only by an explicit
  pull, never by the five-second session status poll or another background refetch.

The `impeccable` design skill influenced this pass through restraint: it reinforced using the
existing native chrome, shared spacing hierarchy, and purposeful interaction states rather than
inventing any new visual language. The frozen spawn tokens and round-3 APIs remained authoritative.

## Deviations from the plan

1. `WorkspaceListScreen` does not mount a second `Screen` component. G-01 already put the route
   under `Screen padded={false}`; nesting another scaffold would create two layout owners. G-04
   removed the feature-level safe-area wrapper and uses that existing route scaffold. The
   new-workspace full-window form does mount `Screen` because it needs its own scroll/footer
   policy inside the dialog.
2. `mobile/src/data/queries/workspaces.ts` required no code change. The background session poll was
   already correctly configured, and `WorkspaceListScreen` already separated `manualRefreshing`
   from query `isRefetching`. G-04 retained it and strengthened the regression test instead of
   rewriting working query logic.
3. Full-tree lint and Jest are not green at this shared-tree snapshot because G-05 was actively
   replacing workspace-detail components. Per ownership rules, G-04 did not edit those files.
