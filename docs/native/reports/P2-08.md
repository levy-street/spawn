# P2-08 — Settings, profile, appearance, and device trust

## What I built

Implemented the native Settings tab as a nested Expo Router stack with exactly nine settings
panels, plus the separate read-only Profile modal described by the research.

- A Settings root with the authenticated account summary and exactly these panel entries:
  Account, Appearance, Notifications, Hosts, Agents, Skills, Templates, Browser devices, and
  Device trust. There are no Terminal, Sessions, or Security panels.
- Shared native settings screen, section, link-row, toggle-row, information-row, and unavailable
  state components using the frozen theme/UI primitives and 44-point controls.
- Account verification resend, sign out, inline permanent-deletion confirmation, server error
  display, and deletion cleanup for credentials, device identity, host pins, theme, notifications,
  onboarding skip state, query data, and connection state.
- Device-local Appearance mode through `useThemeMode()` and the existing `ThemeProvider` storage.
- Device-local notification preference parsing/persistence using the reference
  `spawn.notify.prefs` schema, exact defaults, deduplicated/newest-200 muted sessions, live alert
  stream status, tactile/local sound test behavior, and an explicit remote/system-notification
  unavailable state for Expo Go.
- A settings-side Hosts summary that polls/sorts like the reference and links to the P2-06 Hosts
  surfaces rather than duplicating host management.
- Complete account-scoped Agents CRUD, environment editing/validation, built-in read-only state,
  and per-account yolo preferences.
- Complete account-scoped Skills CRUD with the documented validation, defaults, labels, limits,
  and delete confirmation.
- Template summaries, rename, change-image/use-initials, and delete controls.
- Browser-device registration for this phone, locally derived fingerprints, this-device marking,
  rename, trust counts, serial per-host endorsement, revoke/self-revoke cleanup, revoked-device
  history, pruning, and recovery/error states.
- Device-trust identity/storage/endorsement diagnostics, active and revoked local host pins, local
  trust removal, passkey metadata, and honest unavailable states for every PRF-dependent action.
- Profile identity, account link, Legion totals, privacy-safe stat copying, machines, activity
  heatmap/statistics, and agent usage.

## Shipped control inventory

| Panel | Scope | Controls and states shipped |
|---|---|---|
| Account | Account + local cleanup | Signed-in email; unverified-email callout; Resend verification email; Log out; Delete account…; confirm-email field; Password field/provider hint; Permanently delete; Cancel |
| Appearance | Per device | Light / Always light; Dark / Always dark; System / Match this device; current system preference |
| Notifications | Per device | An agent finishes; An agent is waiting for you; A session exits or is killed; In-app message; Sound; System notification unavailable; Vibration; Alert stream state; Send a test alert |
| Hosts | Account/host links | Open Hosts; Connect a host; online-first host summary with OS/arch/version/session count |
| Agents | Per account | Add/Edit/Delete; Name; Kind; Command; Install command; Yolo arguments; Environment name/value rows; Add/remove variable; built-in read-only badge; yolo switch; Save/Cancel |
| Skills | Per account | Name; Description; Content; Grant to new sessions by default; Add/Update; Edit; Delete/confirm; loading/empty/error states |
| Templates | Per account | Per-row icon/name/tab-window-agent summary; Change icon; Choose image…; Use initials; Rename/Save/Cancel; Delete template/confirm |
| Browser devices | Local identity + account records | Automatic/retry registration; current-device fingerprint; current trust state; Rename; Approve… with exact fingerprint comparison; Revoke; Start fresh after self-revoke; revoked-device disclosure; Clear history; Connect a host recovery |
| Device trust | Local pins + account metadata | Identity fingerprint; trust-store status; endorsement state; Set up/Unlock/Add backup/Revoke unavailable states; passkey rows; active/revoked host pins; Forget trust on this device; Connect a host |

Persistence routing is deliberately split:

- Theme and notifications use AsyncStorage on this device only.
- The Ed25519 seed uses P1-06 SecureStore identity APIs; host pins use its SQLite store.
- Account, agent, skill, template, browser-device, endorsement, and passkey metadata operations use
  the P1-05 REST endpoint layer and TanStack Query invalidation.

## Deviations from the plan

1. The plan points to `research/12 §3` for settings, but the actual complete settings inventory is
   `research/12 §11`; §3 is Login. I used §11 and the cited trust/notification material.
2. Hosts settings link into P2-06's native Hosts/Connect surfaces and show a read-only summary
   instead of duplicating rename/remove forms. This follows P2-08 §3.1's explicit “link rather
   than duplicate” rule.
3. The template image chooser supports initials and bounded local image data, but it does not
   rasterize to the web picker's 96-pixel output or show host-folder suggestions. P2-03's reusable
   picker was a same-phase implementation with no frozen contract, so P2-08 could not import it
   under the campaign dependency rule.
4. No email-change or authenticated password-change control was invented. The reference Account
   panel and current API have neither; the Password field exists only in permanent-deletion
   confirmation, exactly as `research/12 §11.2` documents.
5. Native wording substitutes “this device” for browser-only wording where needed. Labels and
   action/error copy otherwise follow the quoted reference strings.

## Known gaps

- Passkey PRF saved-trust actions and background remote push remain intentionally unavailable in
  Expo Go; each has an explicit reason and supported endorsement/direct-pairing alternative.
- Local notification sound and the native modal/navigation feel still require the campaign's
  later physical-iPhone verification. No app, simulator, or Expo Go launch was attempted here.
- The default registration label is `iPhone` because the fixed dependency set has no Expo device-
  name module; fingerprints, not labels, remain the trusted identity.
- Template images selected here are bounded but not rasterized; see the integration request above.
