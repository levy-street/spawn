# P4-03 — pending agent-command delivery

## What I built

- Connected persisted agent launches to the mounted session transport's frozen `state` event.
- Delivery waits for the transport's five-gate `ready` state; `idle`, `signalling`, `connecting`,
  and `reconnecting` never write terminal input.
- Commands are UTF-8 encoded, terminated with the terminal return byte (`\r`, matching the
  reference terminal input contract), chunked at the shared 64 KiB PTY bound, and written only
  through `SessionTransport.write()`.
- Added an at-most-once durable claim: the session-specific manifest records `delivered: true`
  before command bytes leave JavaScript. Successful delivery clears the manifest and command
  chunks. A crash after the claim can omit a launch, but cannot replay it into a user's shell.
- Serialized claims for the same session so two mounted transports cannot both receive command
  bytes.
- Preserved version-1 persisted manifests by treating a missing `delivered` field as `false`.
- Added abandonment for expired records and sessions that are `exited`, `killed`, or confirmed
  missing. `starting` and `running` remain live; unknown future statuses are not guessed dead.
- Added honest terminal notices for stale, unreadable, dead-session, and unconfirmed-delivery
  outcomes. Missing records and successful launches remain quiet.
- Removed the unused `TerminalCommandSink` delivery path, so production delivery can no longer
  bypass `SessionTransport.write()` or fire before transport readiness.

## Deviations from the plan

- I used the explicitly permitted small integration in
  `mobile/src/components/terminal-ui/terminal-overlay.tsx`. The launcher-owned query layer cannot
  observe a session's actual transport instance or its five-gate readiness without this mount
  boundary. No terminal worker, transport implementation, or terminal route was changed.
- The plan says “newline”; the transport sends `\r`, the terminal Return byte used by the reference
  implementation and existing native key encoder. This is the correct PTY command terminator, not
  a change to the constructed command.
- No app, simulator, Expo Go session, or manual test was run, per campaign rules.

## Known gaps

- Exactly-once delivery cannot be transactional across SecureStore and a PTY side effect. The
  implementation intentionally guarantees **at most once**: after a durable claim, an app crash
  may leave a bare shell and produce an unconfirmed-delivery notice on the next open, but it will
  not risk retyping a command that may already have been sent.
- Device behaviour remains unverified by design; the campaign reserves Expo Go/iPhone testing for
  the human verification pass.
