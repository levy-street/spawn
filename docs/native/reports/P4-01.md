# P4-01 — Server connectivity and About routing

## What I built

- Added user-input URL normalization with whitespace trimming, trailing-slash removal, HTTPS
  defaulting, explicit HTTP support, and rejection of invalid schemes, credentials, queries, and
  fragments.
- Made the base-URL resolution result explicit: persisted runtime override →
  `expo.extra.apiUrl` → compiled default. The resolver now exposes the winning provenance for UI.
- Added `expo.extra.apiUrl` with a documented placeholder, changing no other Expo configuration.
- Built a native Server panel that shows the effective URL/source, validates and persists a new
  URL, tests `<origin>/healthz` without bearer credentials, and surfaces the actual HTTP/network
  failure.
- Changing the URL clears the current server-scoped token before switching, resets live
  connections and query state, and routes to Login. The panel warns about that sign-out before the
  action.
- Added Settings routes for Server and the existing About/Security component, plus visible rows
  that navigate to both.
- Added focused behavior tests for normalization, provenance order, health-check success/failure,
  token-clear ordering, cleanup/sign-out, and Settings navigation.

## Owner action required

`https://spawn.example.com` is a placeholder, not a known production origin. Before the first
physical-iPhone login, replace this one line:

```json
// mobile/app.json:74
"apiUrl": "https://spawn.example.com"
```

with the owner's reachable spawn server origin. After login, Settings → Server can persist a
device-local override instead. Resolution order is:

1. AsyncStorage override at `spawn.api.base-url.v1`.
2. `expo.extra.apiUrl` from `mobile/app.json`.
3. Compiled development fallback `http://localhost:8000`.

Until the signed-out integration request below lands, editing `mobile/app.json:74` is required for
a first login on a physical phone.

## Deviations from plan

1. The signed-out Login affordance is not implemented. The assignment explicitly restricts
   P4-01 to the listed files, but Login, the auth route group, and AuthGate's public-path allowlist
   are owned elsewhere. The new Server panel is reusable for that integration; touching those
   files here would violate path ownership.
2. The actual Settings row composition lives in the unowned
   `mobile/src/components/settings/settings-root.tsx`, while P4-01 owns only the route index. To
   make the rows live now without editing that file, the owned route preserves the existing root
   composition and appends the two new rows. This duplicates the small root composition and should
   be consolidated by its owner.
3. The new child routes are discovered by Expo Router, but explicit native-stack titles were not
   added because `mobile/src/app/(tabs)/settings/_layout.tsx` is outside P4-01 ownership.

No research report was contradicted; this defect-fix plan was based on the P3 parity audit.
