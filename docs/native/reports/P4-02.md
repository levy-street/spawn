# P4-02 — Shell wiring: confirm host, pairing route, and Skip Host

## What I built

- Mounted the promise-backed `ConfirmHost` exactly once in `AppProviders`, below the theme and
  before the router child. Global workspace archive/delete confirmations now settle on accept,
  dismiss, and supersession.
- Mounted `BottomSheetModalProvider`, which was the other missing global overlay dependency.
  Existing `Sheet`, `ActionSheet`, and sheet-backed `Select` instances now have their required
  host in the application tree.
- Added `(onboarding)/host.tsx` as a standalone alias of the existing `device` pairing screen.
  I chose the plan's add-a-route option because a route sweep found existing callers in Hosts,
  Settings, Legion, and device-trust recovery surfaces. The aliased screen already renders only
  `PairingScreen`, so a returning user does not see first-run welcome framing.
- Extended the pure auth-gate decision with `hostSkipped`. The bootstrap reads the existing
  persisted skip value before resolving an authenticated destination, falls back safely to the
  onboarding gate if storage cannot be read, and sends zero-host skipped accounts to Workspaces.
- Kept standalone `device` and `host` pairing paths reachable for authenticated accounts after
  onboarding without allowing them to bypass required email verification.

## Overlay host audit

| Surface | Global requirement | Mount status shipped |
|---|---|---|
| Imperative `confirm()` | `ConfirmHost` | Mounted once in `AppProviders`, before the router child |
| Toasts | `ToastProvider` (owns its rendered queue) | Already mounted; retained |
| `Sheet` | `BottomSheetModalProvider` | Newly mounted in `AppProviders` |
| `ActionSheet` and sheet-backed `Select` | No separate host; compose `Sheet` | Covered by `BottomSheetModalProvider` |
| Keyboard-managed overlays/input | `KeyboardProvider` | Already mounted; retained |
| `Dialog` and local `Confirm` | Self-hosted React Native `Modal` | No global host required |
| `Popover`, `Menu`, and `Tooltip` | `Popover` self-hosts a React Native `Modal` | No global host required |
| `SwipeDismissOverlay` | Self-hosted React Native `Modal` | No global host required |
| Alert presentation | `AlertPresenter` | Already mounted once in `RootNavigator`; retained |

No `ActionSheetHost`, generic `SheetHost`, or separate popover host is declared in the shared UI
implementation.

## Provider order as shipped

Outer to inner:

1. `SafeAreaProvider`
2. `GestureHandlerRootView`
3. `ThemeProvider`
4. `LaunchAppearance` (internal launch side-effect boundary)
5. `BottomSheetModalProvider`
6. `QueryClientProvider`
7. `RealtimeProvider`
8. `ToastProvider`
9. `KeyboardProvider`
10. `ConfirmHost`
11. Router child

`ConfirmHost` and the router are siblings inside `KeyboardProvider`, with the host rendered first.
This leaves both below the theme and all global providers while allowing every route to use the
module-level confirmation service.

  reported missing `ConfirmHost`, as required by section 3.1.
