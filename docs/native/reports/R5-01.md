# R5-01 — Bottom nav, profile menu, and square header controls

## What I built

- Added a persistent, solid bottom navigation bar for Workspaces, Hosts, and Settings. It uses the shared icon/text/theme system, foreground versus muted selection colour, a themed top hairline, an icon-over-label layout, selection haptics, `router.replace`, and its own bottom/side safe-area insets.
- Mounted the bar once below the drawer `Stack` in a flex-column shell. Exact route gating shows it only on `/workspaces`, `/hosts`, and `/settings`; pushed workspace, host, settings, Legion, admin, and terminal routes do not receive it.
- Added `AppHeader.leading` plus a layout-level default-leading provider. The drawer layout supplies a profile control only on the three root routes, so root screens show the avatar even where their existing unowned code still declares `onBack`; pushed screens continue to show the standard chevron. The header never renders both.
- Built the profile control from the shared `Monogram` and the same square action-target token as header icons. It opens the shared bottom `Sheet` with Profile and Log out rows. Profile pushes `/settings/profile`.
- Mirrored `AccountPanel.signOut` exactly for Log out: tolerate a failed logout request, reset the connection store, clear the React Query client, and replace navigation with `/login`.
- Fixed the stretched header buttons at the global primitive. The large shared icon button carried a 52pt minimum height into the 44pt header target; `AppHeader` now constrains height, width, minimum height, and minimum width to `sizing.appHeader.actionTarget` for back and trailing actions. The profile trigger uses the same geometry.
- Added sizing tokens only for the new profile glyph and bottom-nav geometry. The Impeccable guidance kept this pass restrained and consistent with the established native theme and global primitives.

## Deviations and why

- The Workspaces destination uses the existing shared `Shapes` glyph. `LayoutGrid` is not in the shared `IconName` set, `components/ui/icon.tsx` is outside R5-01 ownership, and the brief explicitly permits the existing workspace glyph.
- The project has no `.impeccable.md`; creating the skill's persistent design-context file would violate strict path ownership. I used its production-UI guidance within the frozen round direction and did not create an out-of-scope root file.
- No root screen consumer was edited. Root profile injection therefore lives in the owned layout/header boundary, which is also what guarantees the control appears consistently across all three roots.
