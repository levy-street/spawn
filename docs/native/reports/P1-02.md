# P1-02 — UI overlays

## What I built

Implemented the complete native overlay primitive set owned by P1-02:

- `SwipeDismissOverlay`: full-screen fade/translate presentation, downward manual gesture activation,
  header-only gesture starts, asymmetric rubber-banding, velocity-projected dismissal, interruptible
  settle/dismiss animations, safe-area-aware header arbitration, and one threshold-crossing haptic.
- `Sheet` and `SheetHeader`: Gorhom v5 modal sheet, controlled present/dismiss lifecycle, snap points,
  dynamic sizing, safe-area caps, backdrop dismissal, tokenized surface/handle, interactive keyboard
  behavior, and selection haptics only when the snap index changes.
- `Dialog`: centered `sm`/`md`/`lg` and edge-to-edge `full-mobile`/`viewer` surfaces, modal scrim blur,
  fade plus 95%-scale entrance, reduced-motion fade-only behavior, safe areas, accessible scrim and
  close controls, header/description/footer composition, and exact design tokens.
- `Confirm`, `ConfirmHost`, `confirm()`, and `useConfirm()`: controlled and promise-returning confirm
  patterns, safe/destructive actions, exact default labels, cancellation through the scrim/back action,
  and cancellation of the prior promise if a second request races it.
- `Toast`, `ToastProvider`, and `useToast()`: default/success/error variants, safe-area-aware five-item
  stack, exact-duplicate refresh, semantic success/error haptics, expiry timers, animated removal,
  optional detail/icon/action, manual dismissal, and UI-thread horizontal swipe dismissal.
- `Menu`: viewport-aware anchored action menu with item/label/separator entries, destructive and disabled
  states, the distinct popover border/accent palette, minimum native touch targets, and selection haptics.
- `ActionSheet`: content-sized bottom action list, destructive/disabled states, detail/icon support, and a
  separate cancel affordance.
- `Popover`: native port of the web flip/shift/cap positioning algorithm, including cross-edge flipping,
  safe-area gutters, horizontal sides, centered tooltip alignment, measured content, correct animation
  origin, configurable overlay layer, and noninteractive/interactive semantics.
- `Tooltip`: long-press activation, measured anchor, fade-only motion, centered edge placement, safe-area
  clamping, and accessible hint/trigger behavior.
- `Collapse`: measured animated-height disclosure that remains mounted, remeasures dynamic content,
  clips while closed, hides closed descendants from accessibility, and honors reduced motion.

## Public component APIs

### Swipe-dismiss overlay

```ts
export type DragHandleRegion = "full" | "header";

export interface SwipeDismissOverlayProps extends PropsWithChildren {
  visible: boolean;
  onDismiss: () => void;
  dragHandleRegion?: DragHandleRegion;
  dismissThreshold?: number;
  backdropOpacity?: number;
}

export function SwipeDismissOverlay(
  props: SwipeDismissOverlayProps,
): React.JSX.Element | null;
```

`dismissThreshold` is a projected Y endpoint in points. When omitted it is 22% of the screen height.
`dragHandleRegion="header"` allows activation only when the initial touch is inside safe-top plus the
44-point native header target; the rest of the surface remains available to terminal scrollback.

### Toast

```ts
export type ToastVariant = "default" | "success" | "error";

export interface ToastShowOptions {
  detail?: string;
  variant?: ToastVariant;
  icon?: ReactNode;
  durationMs?: number;
  onPress?: () => void;
  actionLabel?: string;
}

export interface ToastProps {
  toast: ToastRecord;
  onDismiss: (id: string) => void;
}

export interface ToastApi {
  show(message: string, options?: ToastShowOptions): string;
  success(message: string, options?: Omit<ToastShowOptions, "variant">): string;
  error(message: string, options?: Omit<ToastShowOptions, "variant">): string;
  dismiss(id: string): void;
  clear(): void;
}

export function Toast(props: ToastProps): React.JSX.Element;
export function ToastProvider(props: PropsWithChildren): React.JSX.Element;
export function useToast(): ToastApi;
```

`show()` and its semantic wrappers return the live toast ID, or an empty string for blank copy. Exact
live duplicates match on variant/message/detail and refresh their existing ID/expiry instead of stacking.
Default/success live for the tokenized 5 seconds; errors live for 8 seconds unless overridden.

## Exported pure logic

```ts
export interface DismissalDecisionInput {
  translationY: number;
  velocityY: number;
  threshold: number;
  projectionSeconds?: number;
}

projectedDismissalEndpoint(inputWithoutThreshold): number
shouldDismissOverlay(input: DismissalDecisionInput): boolean
rubberBandTranslation(translationY: number, height: number): number
pointPopoverAnchor(x: number, y: number): PopoverAnchorRect
positionPopover(input: PopoverPositionInput): PopoverPosition
toastQueueReducer(state: readonly ToastRecord[], action: ToastQueueAction): ToastRecord[]
```

- `projectedDismissalEndpoint` projects `translationY + velocityY × 0.2s` and clamps upward results to
  zero. The optional projection horizon makes boundary cases directly testable.
- `shouldDismissOverlay` compares that endpoint to the caller/default threshold. Positive fast flicks can
  commit early; upward velocity can cancel a distance that has only just crossed the raw threshold.
- `rubberBandTranslation` preserves direction and resists displacement nonlinearly, with stronger
  resistance above the closed top bound than during the downward dismissal drag.
- `positionPopover` reproduces preferred-side fit, opposite-side flip, roomier-side selection, cross-edge
  flip, final clamp, safe-area gutter, available-size cap, resolved side, and animation-origin semantics.
- `toastQueueReducer` stacks distinct notices, refreshes exact live duplicates, keeps the newest five live
  notices, preserves leaving rows until explicit removal, and handles dismiss/remove/clear independently.

`useReducedMotionPreference()` is also exported from `swipe-dismiss-overlay.tsx`; it tracks the platform
setting and is shared by P1-02 animation surfaces.

## Deviations from the plan

1. The positioning report documented the flip/shift contract but not its full branch-by-branch math. I
   consulted `web/src/components/ui/menu-position.ts` and its tests only for that silent implementation
   detail. The report was accurate; no research correction was necessary.
2. The requested props do not give `SwipeDismissOverlay` ownership of the already-rendered route beneath
   an `overFullScreen` native modal. The component therefore dims the underlying route and subtly scales
   its own card during drag; scaling the actual previous route remains navigator-owned. Adding an implicit
   portal/overlay manager or an unrequested background render prop would violate the scope rules.
3. Destructive confirms put Cancel first, but cannot programmatically move native accessibility focus to
   it because P1-01's shared `Button` does not forward a host ref. The visual/action behavior is complete;
   the ref request is below.
