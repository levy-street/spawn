# P4-05 — Host-control capabilities and streaming

## What I built

Extended the production host-scoped `spawn.host.ctl` transport without changing session terminal
transport behavior.

- Decodes each daemon generation's `hello` before publishing `ready`, exposing an immutable,
  typed capability/limit snapshot.
- Makes whole reads, ranged reads, read-head, and QuickLook preview streams available through the
  existing production `HostTransport` object. This satisfies P2-07's current `readFile`,
  `readHead`, and `previewImage` method probes on supported daemons.
- Implements verified incoming streams with exact ascending sequences, non-empty chunks capped at
  8 KiB, incremental SHA-256, declared/end/local length and digest agreement, a four-chunk
  `ReadableStream` high-water mark, ACK-on-pull, a maximum eight-chunk authorized window,
  cancellation tombstones, and a 60-second inactivity timeout.
- Implements outgoing `writeStream` and repeatable-source `writeFile` paths with 8 KiB chunking,
  local SHA-256 verification, worker acknowledgements, WKWebView DataChannel backpressure at
  256 KiB, cancellation, the 512 MiB hard ceiling, and daemon `stream.committed` completion.
- Preserves atomic publication semantics: an interrupted pre-final write sends `stream.cancel`
  and never sends `stream.end`; acknowledgement loss after final dispatch becomes
  `outcome_unknown` and is never automatically retried.
- Implements direct source-host to destination-host streaming through `transferFileTo`, retaining
  independent source and destination integrity validation.
- Regenerated the single-file offline worker asset. It still has no remote script/style loads and
  retains only the approved `https://spawn.local/` base sentinel.

## Capability shape for P2-07 to adopt

`createHostTransport()` now returns `StreamingHostTransport`. The more permissive base
`HostTransport` keeps the new members optional so existing lightweight test doubles remain source
compatible, but every production instance provides them.

```ts
interface HostCapabilities {
  protocol: "spawn.host.ctl";
  version: 1;
  operations: readonly string[];
  limits: {
    frameBytes: number;
    chunkBytes: number;
    fileBytes: number;
    rangeBytes: number;
    previewBytes: number;
    previewPixels: readonly (128 | 256 | 512 | 1024)[];
    normalQueue: number | null;
    fastQueue: number | null;
  };
}

transport.capabilities: HostCapabilities | null;
transport.hasCapability(operation: string): boolean;
```

Operation gates:

- Whole preview/download: `fs.read`
- Bounded text head: `fs.read.range`, unless the known file size is already within the head limit
- Host-rendered preview: `fs.preview`, plus `limits.previewPixels`
- Explorer upload/destination transfer: `fs.write.begin`
- Cross-host transfer: source `fs.read` and destination `fs.write.begin`

Production stream methods are:

```ts
readFile(path, options?): Promise<HostReadableFile>;
readRange(path, offset, length, options?): Promise<HostRangeFile>;
readHead(path, limit, options?): Promise<HostReadHead>;
previewImage(path, maxPixels, options?): Promise<HostPreviewFile>;
writeStream(stream, declaration, options?): Promise<HostWriteResult>;
writeFile(source, destination, options?): Promise<HostWriteResult>;
transferFileTo(destination, path, destinationDirectory, options?): Promise<HostWriteResult>;
```

An absent or malformed-optional capability list degrades to an empty operation set. Stream methods
then reject immediately with `unsupported_operation`; they do not dispatch a request that can
hang on an old daemon. Advertised numeric limits are bounded by the protocol's hard ceilings.

## Deviations from the plan

1. The base `HostTransport` declares capability/stream members as optional to preserve Phase-2
   structural test doubles that implement only unary requests. Production callers receive the
   required `StreamingHostTransport` subtype from `createHostTransport`; runtime behavior is not
   optional.
2. `host-transport.ts` and `host-ctl-codec.ts` exceed the campaign's approximate 400-line target.
   The assignment's exact ownership list allowed these two implementation files but no additional
   transport modules. Responsibilities remain separated: signalling/public facade in
   `host-transport.ts`, and wire validation/hash/stream lifecycle in `host-ctl-codec.ts`.
3. Atomic filesystem rename/fsync behavior cannot be reproduced in an offline mobile unit test;
   it is daemon-owned. The mobile tests prove the client-side wire invariant that interruption
   before final dispatch sends cancel and never exposes the commit boundary.
