# F-05 — List stability, list rhythm, and launcher wiring

## What I built

- Decoupled the workspaces FlashList pull-to-refresh indicator from TanStack Query background
  state. Only a user pull now sets `refreshing`; the five-second session poll remains invisible.
- Made foreground-only polling explicit for both workspace-list and workspace-detail session
  queries with `refetchIntervalInBackground: false`.
- Preserved FlashList identity, stable workspace IDs, and stable derived `data` identity when only
  query fetch state changes.
- Verified and regression-covered both active-tab add-pane affordances (workspace-header `+` and
  pane-list Add) presenting `LauncherSheet` with the active tab ID.
- Published a successful launch into both session-detail and session-list caches immediately,
  then awaited invalidation of the active workspace, workspace list, and sessions. The launch
  request is covered as carrying `workspace_id`, active `tabId`, and computed tile placement.
- Audited every workspace screen action prop. Header, tab strip, pane list, pane/tab/workspace
  sheets, rename, confirmation, and launcher actions all receive callable handlers; no other dead
  action was found.
- Tightened list rhythm to the web-derived phone targets while preserving 44pt interaction:
  - workspace row: 44pt touch target around a 40pt rounded visual row;
  - workspace mark: 24pt in a 36pt icon slot;
  - workspace list/header gutters: 10pt; header: 48pt; heading: 14/20 medium;
  - workspace tabs: 44pt touch target around a 32pt r8 surface with 6pt gaps;
  - pane list: 3pt outer inset, 6pt gaps;
  - terminal/files/missing pane rows: min 56pt, 12pt horizontal / 8pt vertical padding, r8,
    `paneDivider` seam.
- Updated the owned workspace route test import for the concurrent `(tabs)` to `(drawer)` move.

The Impeccable frontend skill reinforced use of the existing design language and token system;
all geometry and colors above come from shared theme tokens rather than new literals.

## Deviations from the plan

- The current starting tree already contained the correct `WorkspaceDetail` → `LauncherSheet`
  state/prop wiring, despite the diagnosis snapshot saying no handler was supplied. I did not
  replace working code. I added integration coverage for both add-pane entry points and made
  successful launches visible in the session cache immediately.
- The workspace header retains its overflow action so workspace rename/add-tab functionality is
  not hidden. It was otherwise reduced to a 48pt, 14/20 title treatment; the global burger/drawer
  remains the navigation agent's responsibility.
- The 8pt visual gap between workspace rows is produced by a 44pt touch wrapper around a 40pt
  visual row plus a 4pt separator. This keeps visual density and non-overlapping 44pt targets.
- I applied foreground-only polling to the workspace-detail session query as well as the list
  query because it is the same five-second session data policy and is within F-05 ownership.
