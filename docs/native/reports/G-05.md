# G-05 — Workspace tabs and controls

## What I built

- Replaced the compact sliding tab indicator with separate 160pt filled tabs, 6pt gutters, and a
  connected 6pt foot for a populated active tab. Active and inactive states use the existing tab
  surface tokens rather than an outline or underline.
- Added an always-visible 44pt close target to every tab when more than one tab exists. Empty tabs
  close directly; tabs containing non-widget sessions use `Close {name}?` confirmation, settle all
  session deletions, and only then remove the tab. Any deletion failure leaves the tab in place.
- Added 300ms long-press-then-drag reorder with fixed-slot neighbor-midpoint crossing, UI-thread
  sibling displacement, insertion marker, pickup/index/drop haptics, accessibility announcements,
  reduced-motion behavior, and 48pt edge auto-scroll up to 720pt/s. Only the final absolute index
  is sent to the existing optimistic whole-envelope patch path.
- Kept the action-sheet Move left/Move right commands as the non-drag accessibility fallback.
- Disabled the tab Add control at eight tabs with an accessibility reason and stable busy geometry.
- Moved workspace title/actions into the native-stack header. The native automatic back button now
  owns back navigation and the screen no longer adds a second safe-area/header inset.
- Made a blocked header `+` actionable: tapping it now shows “This tab is full. A tab can contain up
  to 16 panes.” The workspace `...` remains wired to workspace actions.
- Rebuilt terminal, files, and unavailable-pane rows on `ListRow height="tall"`, retaining tap,
  long-press, swipe, status, and explicit trailing-action behavior.
- Replaced both compact pane Add placements with one full-width “Add terminal or files” treatment;
  a full tab shows the 16-pane reason visibly and accessibly.
- Added explicit reasons to disabled move, duplicate, close, and add commands in action sheets.

## Deviations from the plan

1. G-00 freezes `ListRow` tall at 76pt while R18's generic narrative says 72pt. G-00 explicitly
   wins, so all pane rows use the frozen 76pt role.
2. One G-05 sentence associates tab drag with `applyMobileOrder`, but R18 §3 and R07 §8 distinguish
   the operations: tab reorder moves the tab array and must preserve every tab's geometry;
   `applyMobileOrder` rewrites geometry only for explicit pane-row reorder. The implementation uses
   `reorderTab` for tab drag and retains/tests `applyMobileOrder` for pane order.
3. The connected tab uses R18's explicitly permitted straight 6pt foot fallback rather than masked
   6×6 concave joins. React Native has no existing shared mask primitive for this chrome.
4. The old custom workspace header was not retained. G-00 requires native chrome, and G-01 already
   supplies a native-stack header plus `Screen`, so G-05 configures its title/actions through that
   header and lets the automatic native back button replace the custom Back callback.

## Known gaps

- No app, simulator, Expo Go launch, screenshot, or manual/visual test was performed, per campaign
  rule. Gesture feel, native header spacing, haptics, and WKWebView-adjacent touch arbitration remain
  physical-device acceptance items.
- Automated tests prove drag geometry and final persistence decisions, not RNGH/Reanimated's actual
  finger tracking or UI-thread frame rate on hardware.
- The connected-foot fallback is intentionally straight; concave masked joins remain optional
  visual refinement if a verified Expo Go-compatible primitive is introduced later.
