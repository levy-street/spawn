# P3-01 — App shell, navigation, deep links, and launch assets

## What I built

- Composed the application provider tree in the required dependency order:
  `SafeAreaProvider → GestureHandlerRootView → ThemeProvider → QueryClientProvider →
  RealtimeProvider → ToastProvider → KeyboardProvider → Router`.
  - Safe-area geometry is available before gesture/layout consumers.
  - The theme is available to query-adjacent visual providers and launch appearance.
  - Query state exists before realtime cache effects.
  - Toasts sit inside theme/gesture/realtime state.
  - Keyboard management wraps the routed screen tree.
- Added a single app `QueryClient` with the required web-parity defaults: 10-second stale time,
  no window-focus refetch, and one retry. There is no persisted query cache.
- Used P1-08's `RealtimeProvider`, which already owns `focusManager`/`onlineManager` lifecycle
  wiring; P3-01 does not duplicate it.
- Added the root native stack, theme-following status bar, launch resolver, and global alert
  presenter.
- Added four themed native tab roots: Workspaces, Hosts, Files, and Settings. Tabs use the shared
  icon system, selection haptics only when changing roots, and a Workspaces attention badge
  derived from P2-09's published attention summaries.
- Configured the terminal route at the root as a vertically gesture-dismissable `card` with a
  slide-from-bottom transition and gesture-matched animation.
- Implemented a validated incoming-link map for invite signup, email verification, password reset,
  device pairing, onboarding gates, login/recovery, post-auth resolution, host detail/files,
  Legion, Admin, workspace tab/session focus, standalone sessions, Download, and Security.
- Added one URL subscription path for both cold launch (`getInitialURL`) and foreground links.
  Auth-required intents opened while signed out are retained in process memory and replayed after
  the authenticated Workspaces gate resolves. Bearer query parameters are never logged or stored.
- Held the native splash until bundled fonts load, synchronized the system background to the
  active theme before hiding it, and made status-bar style follow theme changes.
- Replaced all launch-image placeholders with canonical brand-derived 1024×1024 assets:
  - app/adaptive icon rasterized from `web/public/icon.svg`;
  - transparent splash mark rasterized from `web/public/brand/spawnd-icon.svg`.
- Bundled the exact type assets named by the frozen typography module:
  IBM Plex Sans 400/500 and Rowdies 300. The TTFs came from the research-recommended
  `@expo-google-fonts/ibm-plex-sans@0.4.1` and `@expo-google-fonts/rowdies@0.4.2` package archives;
  no package was installed and both font licenses are included.

## Verification

- `npm run typecheck`: passed with no TypeScript diagnostics.
- `npm run lint`: passed; Biome checked 489 files with no fixes required.

The P3-01-focused suite accounts for 24 tests covering provider order/mounting, QueryClient
defaults, four-root tab rendering, terminal presentation options, every documented incoming link
shape, malformed inputs, pending authenticated intent, and cold-start plus foreground URL delivery.

## Owner-input placeholders

- Scheme: `spawn` (already present in `mobile/app.json` and exported as `APP_SCHEME`).
- Universal-link host: `spawn.example.com` in `mobile/src/lib/linking.ts`. This is intentionally a

  `assetlinks.json` still require the owner's production values. Generic Expo Go cannot validate
  those entitlements.

## Deviations from plan

1. I did not edit `mobile/src/theme/typography.ts`, because P0-01 owns it and it already exposes
   the exact family constants (`IBMPlexSans_400Regular`, `IBMPlexSans_500Medium`,
   `Rowdies_300Light`) required by the research. The provider loads assets under those existing
   keys instead.
2. I did not edit `mobile/app.json` to add universal-link entitlements or replace bundle IDs.
   P3-01 does not own root config, and the necessary production values are explicitly unknown.
3. `/download` and `/security` resolve to the Settings root with a `section` parameter. P3-02 has
   built the native About content component, but no owned route currently renders it; see the
   request below.
4. The root stack contains the specified terminal-card options, but the terminal route currently
   overrides them locally with disabled gestures and no animation. I did not edit P2-05's route.
5. The research's generic malformed-link error requirement had no quoted product copy. The shell
   uses concise recoverable toast copy rather than inventing a new error screen outside P3-01's
   route ownership.

## Requests for other agents

1. **P2-05 / terminal owner:** remove the local `Stack.Screen` overrides in
   `src/app/terminal/[sessionId].tsx` that set `gestureEnabled: false` and `animation: "none"`, or
   match P3-01's exported vertical-card options. Those local options currently defeat the required
   drag-down dismissal configured at the root.
2. **P2-01 / auth owner:** allow the existing `/device` route while the derived auth destination is
   onboarding. `shouldRenderAuthPath` currently accepts only `/onboarding` and descendants, but
   Expo Router removes the `(onboarding)` group from `src/app/(onboarding)/device.tsx`, producing
   `/device`.
3. **P2-04 / workspace-detail owner:** consume `tab` and `focus` search parameters in
   `src/app/workspace/[id].tsx`; select the requested tab and open/focus the requested terminal
   after ownership/data validation. P3-01 preserves and validates both parameters, but the current
   route reads only `id`.
4. **P3-02 / Settings integration owner:** expose the completed `AboutScreen` through a real
   Settings route or teach the Settings root to consume `section=download|security`. Until then,
   those two required incoming links reach Settings but not their intended content.
5. **Orchestrator/owner:** once production identity is chosen, replace `spawn.example.com` and
   `dev.spawnd.spawn`, then add iOS associated domains and the server-side AASA plus Android app-link
   declarations. This requires editing root config/server deployment outside P3-01's ownership.

## Known gaps

- The terminal drag gesture, `/device` gate, workspace `tab`/`focus` behavior, and About link
  destination remain incomplete until the requests above are applied.
- A stale-but-present bearer token can cause an auth-required deep link to skip the in-memory
  post-login replay path; `AuthGate` still redirects safely to Login, but replay after that rare
  expiry edge needs an auth-boundary pending-intent contract from the auth owner.
- Production custom-scheme/universal-link ownership cannot be proven in generic Expo Go and awaits
  an EAS/TestFlight build with final signing entitlements.
- Launch assets, font loading, status bar, and no-flash sequencing have automated/type-level
  coverage only. Physical-iPhone launch appearance remains part of the later human verification.
