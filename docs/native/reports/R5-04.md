# R5-04 — Workspace search placement and optical alignment

## What I built

- Moved workspace search out of `Screen.footer` and placed it directly below the global `AppHeader`, before the status banner and `FlashList`.
- Kept the existing controlled query callback/filtering path unchanged and preserved pull-to-refresh ownership through `manualRefreshing`.
- Made divider ownership explicit: `AppHeader` supplies the sole hairline above the search, the search section has no border, and the global full-bleed `ListSeparator` supplies the sole hairline below it.
- Removed the status banner's redundant top hairline so its error variant cannot recreate a doubled boundary below search.
- Deleted `SearchField.dock` and its bottom-dock wrapper/styles after an app-wide audit found no other `dock` consumer.
- Corrected search text at the primitive with tokenized overrides: zero vertical padding, an explicit 20pt component-label line height, vertical centring, and an 8pt leading gap instead of the inherited 4pt gap.
- Replaced obsolete dock coverage with primitive optical-alignment coverage, and updated workspace regression coverage for top placement, exact divider ownership, absence from the sticky footer, and the existing stable refresh contract.

The `impeccable` pass kept the correction deliberately restrained: it reused the global header, search, spacing, typography, and separator contracts instead of adding workspace-local chrome.
