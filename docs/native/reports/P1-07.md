# P1-07 — Domain model, layout algebra, selectors, and query keys

## What I built

Implemented the platform-neutral domain layer for workspace/tab/pane meaning and derived state:

- Forward-compatible LayoutV3 domain types, including file widgets and opaque future widget/tile
  fields, while reusing P1-05's Zod-inferred wire types for sessions, hosts, agents, skills,
  templates, and workspace metadata.
- A validating LayoutV3 envelope codec that normalizes omitted tab homes, rejects incoherent
  envelopes, round-trips unknown fields, and never mutates its input.
- The complete deterministic 24×24 grid algebra: validation, reading order, auto-placement,
  split fallback, add/capacity, move/swap, resize, remove/grow, compact, and legacy split-tree lift.
- Immutable tab algebra: active fallback, add/name/rename/reorder/remove, paired homes, pane lookup,
  cross-tab move, removal, and all `can*` predicates. Limits are 8 tabs, 16 tiles per tab, and 4×4
  minimum geometry.
- The mobile/desktop ordering bridge. One to six rows become a deterministic full-width stack;
  seven to sixteen reuse the existing rectangle multiset. Payloads remain attached to pane IDs.
- Five independent display dimensions for sessions: process, server activity, host presence,
  terminal transport, and current attention. Activity boundaries match the server exactly at 3s
  and 8s, and dead process attention outranks waiting.
- Agent identification and launch-command construction for Claude Code, Codex, OpenCode, Aider
  Sonnet, Shell, custom definitions, and unknown/monogram fallbacks.
- Pure tab/workspace/session/host/fleet selectors, including active choices, row projections,
  rollups, attention badges, local new-output state, capacity, availability, and stable ordering.
- The complete function-based query-key registry plus list/detail invalidation groupings.

## Concurrent layout PATCH risk

Every tab or pane operation replaces the entire workspace layout envelope. The server exposes no
revision, ETag, expected-version, or compare-and-swap field. Therefore two clients can read the
same layout and the later PATCH can silently clobber the earlier client's tab, home, widget, or
geometry change. Immutable recipes make each submitted envelope coherent, but cannot solve this
cross-device last-writer-wins hazard. Phase 2 should serialize mutations per workspace, begin each
recipe from a fresh GET, PATCH once, then refetch; it must not claim this prevents cross-device loss.

## Deviations from plan

1. The strict wire schemas cannot represent future/unknown layout fields. `Workspace` therefore
   reuses `WorkspaceOut` metadata but substitutes the preserving domain `WorkspaceLayoutV3` type;
   all other entity types directly alias P1-05's Zod-inferred exports.
2. Invalid envelope geometry is rejected as a whole instead of being repaired or dropped. Unknown
   object fields and future widget payloads round-trip. This is the only behavior that both avoids
   silent data loss and honors the requirement that invalid envelopes be rejected.
3. Invalid mobile reorder permutations are a preserving no-op instead of throwing. A gesture race
   cannot destroy panes merely because its ID list became stale.
4. Files/missing pane projections contain domain facts but no final display copy. Phase-2
   components own the exact user-facing strings under the campaign copy convention.

## Requests for other agents

1. **P1-05 API:** make the workspace layout envelope/tab/grid/tile Zod schemas preserve unknown
   fields and allow an opaque unknown widget object. Zod object parsing currently strips extra
   properties, and the literal `files` widget schema rejects future widget kinds before P1-07's
   lossless codec can preserve them. An alternative is for workspace endpoints to hand the raw
   layout value to `parseLayoutV3` before any stripping occurs.
2. **P1-06 / scaffold or P3-04:** update the shared Jest transform/mocks so ESM-only
   `@noble/ed25519` and `@noble/hashes` load in the crypto/trust tests.
3. **P1-09:** format the remaining terminal worker files and
   resolve the two terminal warnings. P1-07's owned paths are already clean.

## Known gaps

- Cross-device whole-envelope PATCH clobbering remains a server-contract limitation, as detailed
  above. This layer intentionally does not invent optimistic concurrency.
- The API integration request above is required for unknown future layout fields to survive the
  complete fetch-to-PATCH path, not just P1-07's codec/algebra path.
- The full shared lint and test commands are not yet green because of the concurrent-agent issues
  listed under verification and requests; P1-07-owned verification is green.
- Physical-device behavior is intentionally unverified in this automated implementation phase.
