# F-06 — Non-form primitive and typography parity

## What I built

- Made `StatusDot` pulsing explicitly opt-in (`pulse` now defaults to `false`) while preserving
  reduced-motion suppression and the existing geometry/tone recipes.
- Corrected Toast's close control to the web's 20pt visual with a 14pt icon, r6 radius, and 12pt
  hit slop; removed the negative-margin 44pt layout box.
- Corrected Popover to use the existing xl shadow geometry at the audited black-50 overlay opacity,
  derived from the shared `shadow.xl` and `alpha.a50` tokens.
- Changed Collapse to height-only motion using `theme.motion.transition.collapse` (200ms/swift),
  removed the opacity fade, prevented an initially open disclosure from animating, and retained
  the reduced-motion duration.
- Added the web composition slots `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, and
  `CardFooter` with the audited p16/gap4, 16/20/600, 14/20, p16/pt0, and row/gap8 treatments.
- Replaced Chip's Badge alias with a distinct connection-style primitive: h24, px8, gap6,
  11/16 copy, optional leading content, semantic variants, disabled/pressed states, and a 44pt
  footprint through hit slop when interactive.
- Added `uiLg` (18/28), `uiXl` (20/28), `grimoireBody` (15/24), and
  `grimoireBodyLoose` (15/28) composites. Exposed `uiBase`, `uiSmSemibold`, both new UI sizes,
  both sigil roles, and both grimoire body roles through `TextVariant` without changing raw scale
  values or existing variant mappings.
- Audited all owned sources for literal colors. The only matches are the pre-existing runtime
  theme-color alpha encoder in Toast and the token-derived Popover shadow rewrite; neither is an
  independent color literal.

## Deviations from plan

- No test or snapshot file was edited or created because F-06's exact ownership list contains only
  the eight implementation files above, while the campaign rules prohibit writing any unlisted
  path. Existing tests were used for automated verification; the missing focused assertions and
  required snapshot refresh are requested below.
- `Card` retains its legacy `padded=true` default because all current native callsites are outside
  F-06 ownership and rely on it. The new web-style slots are exact when composed with
  `<Card padded={false}>`; changing the default before callsite migration would regress existing
  screens.
- The audit recommends a named overlay-xl token in `theme/effects.ts`, which is outside F-06
  ownership. Popover currently produces the exact target by applying shared `alpha.a50` to the
  existing shared xl geometry.
- The web source was consulted only for Card footer direction/alignment because the research table
  specified its metrics but not that composition detail. No research error was found.
