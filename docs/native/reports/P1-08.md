# P1-08 — Realtime: sockets, lifecycle, and cache coherence

## What I built

Implemented the native realtime control layer under `mobile/src/data/realtime` and its three
transport-local Zustand stores under `mobile/src/data/stores`:

- A generation-fenced reconnecting JSON WebSocket with the full
  `idle | connecting | open | reconnecting | closed | failed` state machine, exact subprotocol
  verification, typed sends, subscribable state, stale-frame rejection, permanent-close
  classification, watchdog retirement, and a global `retireAll()` lifecycle boundary.
- The owner alert client on authenticated `/ws/alerts` with `spawn.alerts.v1`, exhaustive alert,
  ping, and protocol-rejection parsing, malformed-frame isolation, and isolated subscribers.
- Opaque session and host signalling relays on authenticated `/ws/browser`/`spawn.v3` and
  `/ws/host`/`spawn.host.v1`. They never interpret or carry PTY/DataChannel content. Binary
  signalling fails closed; malformed JSON text is ignored.
- Pure `effectsForFrame` cache mapping through P1-07's `qk` registry, with no `QueryClient`
  dependency and no speculative entity patching.
- AppState/TanStack focus wiring, injectable network/TanStack online wiring, hard retirement on
  background/offline/interface change, a serial ordered recovery sweep, and a registration hook
  for P1-09's visible RTC/DataChannel generations.
- `RealtimeProvider`, which mounts the alert client, applies cache effects, performs reconnect
  recovery invalidations, exposes alert connection state/actions, and renders only its children.
- Focused Zustand stores for socket/transport state, transient alerts with bounded 30-second
  dedup/claim semantics, and per-session follow/font/title UI state with close cleanup.

## Socket parameters as implemented

| Client | Heartbeat/watchdog | Reconnect | Permanent failure |
|---|---|---|---|
| Alerts | Server ping expectation is 25,000 ms; client silence watchdog is 80,000 ms and rearms on every frame | Exponential bases 1, 2, 4, 8, then 15 seconds; multiplier is injected random jitter from 0.7 through 1.3; attempt resets on open | 1002, 1008, 1009, 4002, 4003 |
| Session signal | No application watchdog | Linear 500 ms × attempt, capped at 10 seconds | Same shared classification |
| Host signal | No application watchdog | Linear 500 ms × attempt, capped at 10 seconds | Same shared classification |

The alert algorithm follows the cited web implementation exactly: the 15-second cap applies to
the exponential base before jitter, so the literal resulting delay range is 0.7–19.5 seconds.
Every hard retirement and every new connection advances the generation token; callbacks from an
older token are harmless.

There is no direct React Query patch and no singular-session invalidation. This intentionally
matches the web client's current invalidation behavior; there is no invalidation divergence to
report. On alert socket reconnection, the provider performs the recovery sweep because alerts have
no cursor, replay, or durable history.

## Resume and interface-change order

AppState first sets TanStack focus (`active` is focused; `inactive`/`background` are not).
Background retires all registered sockets and registered P1-09 generations, cancelling their
timers. Network updates first set TanStack online state; offline and connected interface changes
then hard-retire all generations.

Every active/online recovery runs this serialized order:

1. Start reconnecting the owner alert socket.
2. Invalidate the `sessions`, `workspaces`, `hosts`, and `agents` prefixes, then refetch any active
   screen keys supplied to `RealtimeProvider`.
3. Reopen P1-09 generations registered through `registerRealtimeGenerationTarget`, then invoke
   the provider's optional visible-transport callback.

Alert socket reconnection after an ordinary unexpected close also runs step 2; this is current
state recovery, not replay.

## `SignalChannel` integration API for P1-09

```ts
export interface SignalChannel {
  readonly state: SocketState;
  send(frame: unknown): void;
  onFrame(fn: (frame: unknown) => void): () => void;
  close(): void;
}

export function openSessionSignal(sessionId: string): SignalChannel;
export function openHostSignal(hostId: string): SignalChannel;
```

Both open functions connect immediately and use P1-05's authenticated URL builders. `send` JSON
encodes exactly one opaque signalling frame and throws while not open. `onFrame` receives parsed
JSON objects and always returns an unsubscribe. `close` is terminal for that channel instance.

Visible WebRTC transports can participate in mobile lifecycle boundaries with:

```ts
registerRealtimeGenerationTarget({
  retire(reason) { /* close RTC, channels, timers, and reject pending operations */ },
  reopen() { /* create one fresh visible generation */ },
});
```

The returned unregister function must run when the transport lease is destroyed.

## Deviations from the plan

1. The installed dependency set contains neither `@react-native-community/netinfo` nor
   `expo-network`. Per the fixed-dependency rule I did not install one. `lifecycle.ts` therefore
   ships the complete reachability behavior behind a tested `NetworkSource` injection, but the
   provider cannot create a production network listener by itself yet.
2. The alert parser preserves web parity by normalizing a missing/invalid `at` to `""`; this is
   explicitly the unresolved research choice. The bounded 30-second dedup prevents rapid repeats
   but an empty timestamp remains a weaker event key.
3. Alert dedup is process-memory-only, matching this plan's in-memory-store instruction. The
   research report's optional persisted quick-restart dedup was not added.
4. Backgrounding fully retires the alert socket rather than keeping it best-effort. This follows
   P1-08 §3.6's explicit background rule; it reconnects and refetches deterministically on resume.
