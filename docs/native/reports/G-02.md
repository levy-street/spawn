# G-02 — Standardise the component system and sizing scale

## What I built

- Added `theme/sizing.ts` as the semantic source of truth for phone spacing, controls, rows,
  headers, footers, cards, empty states, badges, chips, tabs, and type dimensions.
- Wired the legacy `space()` unit and the shared row/gutter/pane/touch aliases in `spacing.ts` to
  the new semantic scale.
- Shipped the frozen `ListRow` API with all four content slots, 64/76pt height roles, pressed
  state, accessible naming, and both press callbacks.
- Shipped the frozen `FooterActions` API with a safe-area-aware opaque bar, 48pt actions, and
  equal-flex one/two-child layout after the canonical 12pt gap.
- Added `SectionHeader` with title, optional eyebrow/description, and optional trailing-action
  anatomy.
- Raised `Button` sizes to 44/48/52pt, retained stable loading geometry and existing variants,
  and moved all owned size literals into `sizing.ts`.
- Standardised Card anatomy/spacing, made EmptyState actions full-width on phone, retained Badge
  parity, and made interactive Chips real 44pt controls.

## Deviations from the plan

1. G-00 freezes `ListRow` at 64pt regular and 76pt tall, while R18 describes a generic 72pt
   primary entity. G-00 explicitly wins; the scale retains 72pt as the separate `rich` row role.
2. R17 §3 and R18 Part A disagree on exact tab geometry. G-02's plan explicitly requires every
   R17 §3 target, so the canonical scale records 56pt strip, 44pt visual, 8pt gap, and 144–200pt
   width. The tab owner should follow its own plan if that plan supplies a later override.
3. R18's generic footer spec says an 8pt action gap, while G-02 explicitly directs footer gaps to
   R17 §5. `FooterActions` therefore uses the exact R17 12pt gap.
4. Badge and most EmptyState geometry stayed at parity as required by the boundary referencing
   research2/13. EmptyState only adopts R18's 20pt icon and full-width phone action behavior.
5. No new Jest file was added: the assignment's exact ownership list contains no test path, and
   the campaign rules prohibit touching even adjacent unowned files. Existing owned-component
   behavior was verified through the already-owned foundation/theme suites and the full run.
