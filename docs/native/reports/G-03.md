# G-03 — Liquid Glass, SF Symbols, native sheets and popovers

## What I built

- Added `GlassSurface` at the frozen G-00 API. It uses Liquid Glass only when the platform is iOS,
  Reduce Transparency is off, and both Expo runtime availability checks pass. Every other state,
  including the initial asynchronous accessibility query, renders an explicit semantic `BlurView`.
- Added the frozen `NativePopover`: anchored placement, a 260pt hard minimum, viewport-aware
  320pt cap, 44pt minimum rows, 20pt chrome symbols, separators, disabled state, semantic
  destructive treatment, backdrop dismissal, and the shared haptic vocabulary.
- Rebuilt `Menu` on `GlassSurface`, raised its default width from 176pt to 280pt, enforced the
  same 260pt minimum, retained richer labels/details/React-node icons, and exposed identity-safe
  aliases for Expo Router's native `Link.Menu` and `Link.MenuAction`.
- Extended `Icon` with an explicit `brand | chrome` variant. Brand/domain icons remain Lucide by
  default. Chrome maps supported intents to monochrome SF Symbols and supplies the original
  Lucide glyph as the Android/web fallback; callers can provide a more specific SF Symbol.
- Added `showNativeActionSheet`, an opt-in UIKit `ActionSheetIOS` entry point for short flat lists.
  It maps cancel, destructive and disabled indices and intentionally omits unsupported icons and
  detail copy. The existing rich cross-platform `ActionSheet` component remains intact.
- Added `NATIVE_FORM_SHEET_OPTIONS` for route-backed Expo Router sheets with fractional 48%/90%
  detents, system grabber and system-owned corner radius. The existing same-route `Sheet` API and
  behaviour remain intact.

## Deviations from the plan

1. The generic `Sheet` component was not forced into `react-native-screens` presentation. Native
   `formSheet` is a route presentation configured on `Stack.Screen`; a mounted component cannot
   create that presentation while preserving the existing API. Every current caller is same-route
   state: launcher, select, diagnostics, font-size, terminal-keys, and the rich cross-platform
   action sheet. The native route options are exported for route owners instead.
2. `ActionSheet` did not silently switch to UIKit. Its existing contract includes icons and detail
   copy and does not say whether an iPhone bottom presentation is acceptable. The explicit
   `showNativeActionSheet` entry point makes that product decision visible and keeps fallback
   behaviour honest.
3. No new Jest file was written because the assignment authorizes only the six exact implementation
   files plus progress/report paths. Existing owned-surface tests were run, but the new glass
   availability and NativePopover branch matrix still needs a test path authorized by the
   orchestrator.
4. Research said `expo-glass-effect` and `expo-symbols` were absent. The assignment and current
   dependency tree superseded that statement; both were already pinned to SDK 54-compatible
   versions, so no dependency files or install commands were touched.

## Known gaps

- A supported native single-tap anchored `UIMenu` is unavailable in Expo Go 54. The tap popover is
  native material around React Native rows; long-pressed navigational links use native `Link.Menu`.
- `isGlassAvailable()` is deliberately false until a mounted `GlassSurface` resolves the async
  Reduce Transparency query. This produces explicit blur during startup instead of a flash of
  unverified glass.
- UIKit action sheets cannot display the current React-node icons/details and cannot be dismissed
  programmatically through the controlled `visible` prop after presentation; use the opt-in helper
  only for short flat command lists.
- No simulator, Expo Go launch, screenshot, or physical-device test was performed, per campaign
  rules. Liquid Glass and anchored geometry still require the campaign's later device pass.
