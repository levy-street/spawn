# R4-05 — Settings UI standardisation

## What I built

- Fixed the Account phantom keyboard by leaving the delete-account `Collapse` mounted for its animation while conditionally mounting its form body only after confirmation expands. The email input still autofocuses at the correct moment, after the user presses **Delete account…**.
- Added the web-parity agent yolo presentation: a shared `Zap` icon plus visible `yolo` label, amber active colour, muted/disabled unavailable state, and an amber `yoloSuffix` in the command preview containing yolo environment keys and arguments.
- Kept the custom-agent and template empty states on the global `EmptyState` primitive inside `SettingsSection`; no call-site border or replacement surface was added.
- Rebuilt `SettingsScreen` composition around `Screen.header` and `AppHeader`, retaining the in-body description as lead copy. Pushed settings/admin pages receive the global back control, and root Settings/Admin headers preserve their prior destinations through `headerDestinationActions`.
- Removed the obsolete outer `Screen` wrappers from every owned settings/admin route so safe-area and header layout are applied once by `SettingsScreen`.
- Updated settings render wrappers for the new header safe-area dependency and added behavioural coverage for the collapsed Account form, single header/back control, Settings destinations, active yolo styling/suffix, and unavailable yolo state.

The Impeccable design-system pass reinforced the implementation choice to reuse global header, empty-state, icon, typography, colour, spacing, and opacity primitives rather than introducing settings-local surfaces or labels.
