# F-03 — Form control styling parity

## What I built

- Raised the visible `Input`, `Select`, and default/inline `SearchField` boxes from 40pt to the
  native 44pt target while retaining 14/20 type, 12pt horizontal inset, and the complete existing
  `purpose` keyboard/autofill matrix.
- Replaced Input/Textarea's focus-time border colour swap with an independent, absolutely
  positioned 1pt animated halo. The resting edge remains `input`, errors keep a destructive edge,
  and a focused error uses a destructive halo. Because the halo is absolute, focus does not change
  measured control height.
- Changed Input/Textarea selection from neutral `ring` to `brandAccent` and retained muted
  placeholders, transparent fill, and 0.5 disabled treatment.
- Added Select error/focus support, a separate focus halo, destructive invalid treatment,
  transparent rest fill, pressed-only accent fill, and a 44pt closed box. Option-sheet behaviour
  is unchanged.
- Added `default`, `sidebar`, and `inline` SearchField variants. The sidebar treatment uses the
  44pt phone adaptation of the web search: radius 10, token-derived 50% muted fill, transparent
  edge, 14pt icon, no halo, and a 44pt clear target around a 24pt visual.
- Removed Field's unconditional helper row and its 24pt void. Help/error content now mounts only
  when non-empty, fades with token timing, and uses a layout transition instead of an abrupt jump.
  Field now uses a 6pt ordinary gap, offers the specified 8pt auth gap and 12/20 auth helper role,
  and propagates a non-empty error to its child control.
- Kept Label's ordinary 14/14/500 role, added the specified auth sigil role, and made the required
  asterisk opt-in via `showRequiredIndicator` so strict web parity does not add it implicitly.
- Kept Switch's 40×24 track and 44pt-high hit area, while correcting focus to a 2pt ring outside
  a real 1pt background-coloured offset. Its 48pt-wide wrapper prevents clipping.
- Audited SegmentedControl and left it unchanged, as research2/13 explicitly says the generic
  native primitive and 0.5 disabled state should remain.

The `impeccable` skill reinforced restraint here: I followed the existing product tokens and the
web parity matrix without introducing a new styling system or a new visual direction.

## Deviations from the plan

1. I did not edit or create form test files because the assignment's exact ownership list includes
   only the eight implementation files. The existing Field tests encode the behaviour being
   removed, so they cannot pass simultaneously with the required no-helper-row result.
2. The scoped Pressroom form skin is not fully wired. React Native View styles do not cascade into
   child controls, and F-03 cannot edit AuthShell, auth call sites, or the theme provider. Field and
   Label expose their specified auth roles, but an owner-authorized shared context is still needed
   to give Input/Textarea fixed grimoire colours, radius 6, sigil type, ember focus/error, and
   hellfire selection inside auth.
3. SearchField variants were implemented but their feature call sites are outside F-03 ownership,
   so existing workspace/folder/terminal uses still receive the default treatment until their
   owners opt in.
4. The Switch research also requires the entire SettingsToggleRow to become pressable, and the
   Appearance use of SegmentedControl to become three radio cards. Those components are outside
   the F-03 file list and were not changed.
