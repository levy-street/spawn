# P2-06 — Hosts, agents, skills and Legion

## What I built

- A native Hosts stack with an online-first, name-sorted list, 10-second polling, pull-to-refresh, status, platform, daemon version, connection mode, bucketed capacity, navigation, and rename/remove actions.
- A host detail surface with 30-second host polling and 5-second session polling. It shows every documented host fact, identity/public-key data, capacity, sessions, and the real Files and Agents & skills destinations.
- Trust-aware destructive removal: the local pin is revoked before the server host delete request, with confirmation copy explaining that existing sessions and future connections stop working.
- Host agent availability, install/update actions, version/update/error/path details, install output, and an optimistic auto-update policy toggle with rollback. Skills are shown as the account-level, read-only definitions described by research.
- Legion fleet rollups from the shared P1 selectors, including totals, hardware, attention state, agent inventory, session counts, and per-host bucketed capacity.
- An opt-in "Go live" exact-capacity path. It opens a signed host transport only while Legion is focused and live metrics are requested, polls without overlap, tears down on blur/toggle-off, and keeps bucketed values clearly distinct from exact samples.
- Fixture-driven tests for documented list/detail fields, absent daemon restart/update/log controls, bucketed versus exact capacity, agent actions and policy wiring, trust-revocation ordering, and Legion selector rollups.

No daemon restart, daemon update, or daemon-log action was added; research confirms those APIs do not exist.

## Deviations from the plan

- The frozen P1-09 `HostTransport` interface has no capability collection or capability-query method. Exact capacity therefore cannot be capability-preflighted. The implementation gates it by explicit user opt-in, signed host identity, focused screen, ready transport, and a successful runtime response; unsupported/error responses remain honest and fall back to the bucketed value.
- Agent install/update controls are capability-gated by the fields returned for each agent endpoint. Skills remain read-only here because the research defines them as account-level data and P2-08 owns their settings mutations.
- Repository-wide verification is not green solely because concurrently edited, unowned paths currently fail. Owned verification is green and no unowned file was changed.
