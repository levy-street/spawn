# P1-03 — UI forms implementation report

## What I built

Implemented the complete shared form layer for the native app:

- `Input`: exact 40pt web geometry, semantic colors, 150ms Reanimated focus treatment,
  disabled/error states, nine coherent mobile input purposes, password reveal, submit forwarding,
  and `nextRef` focus handoff.
- `Textarea`: the same purpose/accessibility/focus model, multiline auto-growth from the web's
  60pt minimum to an overridable maximum, then native scrolling.
- `Switch`: exact 40×24 track, 16pt thumb, 2→18pt travel, token colors/shadow/focus treatment,
  Reanimated timing, selection haptic, a 44pt target, and checked-state accessibility.
- `Label` and `Field`: token typography, required marker, label-to-control accessibility wiring,
  hint/error replacement, destructive error tone, and a permanently reserved helper line so
  ordinary inline validation does not shift the form.
- `SearchField`: leading search mark, non-empty clear action, controlled/uncontrolled operation,
  ref forwarding, and cancellable debounce (250ms default per the plan).
- `SegmentedControl`: generic two-to-four-choice API, equal-width native segments, animated
  selection plate, checked radio semantics, disabled options, and selection haptics.
- `Select`: generic typed values/options, compact `ActionSheet` presentation, sheet/list
  presentation for larger or custom rows, disabled/selected states, custom row rendering, and
  combobox accessibility.
- `validation.ts`: required/email/length/confirmation helpers; distinct signup and reset password
  policies; workspace/session name policies; and exact host-pairing-code alphabet/shape handling.

The `impeccable` design skill was used as a quality lens only. It reinforced touch-target,
hierarchy, restraint, and interaction checks; the implementation introduces no new visual
direction and follows spawn's transcribed tokens and shared atoms.

## Validator contract, rules, and copy

All validators return `string | null`; factories return that same `(value: string)` signature.

| Export | Rule | Error copy |
|---|---|---|
| `validateRequired` | Trimmed value must be non-empty | `This field is required.` |
| `validateEmail` | Empty is left to `validateRequired`; otherwise trimmed value must match a conventional local@domain.tld shape with no whitespace | `Enter a valid email address.` |
| `minLength(n, error?)` | Raw string length must be at least `n` | Default `Use at least {n} characters.` |
| `maxLength(n, error?)` | Raw string length must be at most `n` | Default `Use {n} characters or fewer.` |
| `matchingConfirmation(expected, error?)` | Exact string equality | Default `Both passwords must match.` |
| `validateSignupPassword` | 8–256 characters | `Use at least 8 characters.` / `Use 256 characters or fewer.` |
| `validateResetPassword` | 12–256 characters | `Use at least 12 characters.` / `Use 256 characters or fewer.` |
| `validateWorkspaceName` | Trimmed value required, maximum 128 | required copy / `Use 128 characters or fewer.` |
| `validateSessionName` | Blank is valid (clears the server name), otherwise trimmed maximum 128 | `Use 128 characters or fewer.` |
| `normalizeHostPairingCode` | Trim, uppercase, remove the display hyphen | no error |
| `validateHostPairingCode` | Eight characters displayed as `XXXX-XXXX` or unhyphenated; case-insensitive input; alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` | `Enter the 8-character code from the terminal.` |

Exported boundary constants are `SIGNUP_PASSWORD_MIN_LENGTH = 8`,
`RESET_PASSWORD_MIN_LENGTH = 12`, `PASSWORD_MAX_LENGTH = 256`,
`WORKSPACE_NAME_MAX_LENGTH = 128`, and `SESSION_NAME_MAX_LENGTH = 128`.

The password-minimum and confirmation strings are verbatim authored web copy. Research 12
explicitly records that the web has no authored required/email strings because browser constraint
validation localizes them; the native required/email strings above therefore need product copy
approval and are not represented as web quotations.

## Deviations from plan and research

1. Research 12 contains no authored required or malformed-email error strings. The P1-03 plan
   nevertheless requires those validators, so I supplied concise native inline copy and called it
   out above instead of falsely labelling it verbatim web copy. A read-only check of the cited web
   forms confirmed the report was correct.
2. React Native 0.81 exposes `smartInsertDelete` but not distinct smart-quote or smart-dash props.
   `plain` and `path` explicitly disable capitalization, autocorrect, spellcheck, and
   `smartInsertDelete`; there is no supported additional switch to set without changing the fixed
   dependency/platform contract.
3. The web textarea specifies a 60pt minimum but no maximum. Native auto-grow requires one, so the
   default maximum is the existing 128pt spacing token and remains overridable through
   `maxHeight`.
4. A custom `renderOption` forces `Select` to use `Sheet`, even with six or fewer choices, because
   the delivered `ActionSheetAction` contract supports an icon plus fixed label/detail rather than
   an arbitrary full row. Ordinary compact choices still use `ActionSheet` exactly as planned.
5. The 250ms search debounce is the exact plan value. It is a data callback delay, not visual
   motion; the theme motion table has no 250ms token.
