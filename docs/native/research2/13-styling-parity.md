# R13 — Styling parity audit: web versus native

## TL;DR

- The light, dark, grimoire, spacing, radius, motion, and canonical type tokens are transcribed correctly; the dominant failures are token application and component composition, not token literals (`mobile/src/theme/colors.ts:1-157`; `mobile/src/theme/spacing.ts:1-84`; `mobile/src/theme/typography.ts:85-116`).
- Auth never enters the web's `grimoire pressroom` context, so native auth uses the ordinary app palette, system control type, wrong quiet buttons, and an invented logo instead of the branded surface (`web/src/components/onboarding/auth-shell.tsx:53-55`; `mobile/src/components/auth/auth-shell.tsx:54-106`).
- Native `Input`, `Select`, and `SearchField` show a 40pt box while their embedded actions are 44pt; make the visible phone control 44pt, retain 14/20 type, and add a separate 1pt focus halo (`mobile/src/components/ui/input.tsx:257-315`; `mobile/src/components/ui/select.tsx:183-204`).
- `Field` always reserves a blank 16pt helper line plus an 8pt gap; remove that 24pt void and render help/error copy only when it exists (`mobile/src/components/ui/field.tsx:35-84`).
- Vendor agent logos, workspace monograms, custom workspace images, and the spawnd lockup all drift from web branding; fixed brand constants and role-specific identity components are required (`web/src/components/icons/AgentIcon.tsx:25-34`; `mobile/src/components/workspace-detail/agent-icon.tsx:31-44`; `mobile/src/components/ui/monogram.tsx:5-64`).
- Badge, spinner, skeleton, empty state, sheet, dialog, base menu, tooltip, and most toast geometry are already at or very near exact parity and should not be redesigned (`mobile/src/components/ui/badge.tsx:52-129`; `mobile/src/components/ui/empty-state.tsx:80-109`; `mobile/src/components/ui/dialog.tsx:89-205`).
- The important remaining primitive defects are implicit status-dot pulsing, toast close geometry, popover shadow opacity, collapse timing/opacity, missing Card slots, and the generic Chip alias (`mobile/src/components/ui/status-dot.tsx:57-78`; `mobile/src/components/ui/toast.tsx:261-277`; `mobile/src/components/ui/collapse.tsx:23-59`).
- Native workspace/list rhythm is much looser than web: 72pt rows, 44pt avatars, 16pt gutters, and a 24/32 heading versus web's 40px rows, 24px marks, and 10px sidebar gutters (`mobile/src/components/workspaces/workspace-list-styles.ts:5-27`; `mobile/src/components/workspaces/workspace-row.tsx:229-254`; `web/src/components/nav/sidebar-parts.tsx:9-20`).
- Native typography contains the right raw scale and core composites, but exposes too few semantic variants and never applies the existing sigil roles to auth labels/buttons/inputs (`mobile/src/theme/typography.ts:85-116`; `mobile/src/components/ui/text.tsx:10-43`).
- All recommended fixes use React Native core and the already-installed Expo SDK 54 libraries; no new dependency is required and every recommendation remains compatible with Expo Go (`mobile/package.json:20-70`).

## Audit basis and target rule

The web source establishes `--row-h: 40px`, `--pane-gap: 6px`, sidebar width `264px`, rail width `56px`, base radii `6/8/10px`, and a zero mobile content inset (`web/src/app/globals.css:89-92`, `web/src/app/globals.css:335-345`). Native already carries the same values plus `touchTarget: 44` (`mobile/src/theme/spacing.ts:32-50`, `mobile/src/theme/spacing.ts:58-84`). The prior architecture explicitly requires web design-language parity but native interaction behavior, including a minimum `44×44` interactive target (`docs/native/plan/00-OVERVIEW.md:15-25`, `docs/native/plan/00-OVERVIEW.md:255-259`).

The target rule used below is therefore:

```ts
// Web visual rhythm                         // Native target
rowHeight = 40;                              touchTarget = 44;
inputVisualHeight = 40;                      inputVisualHeight = 44;
buttonDefaultVisual = 40; hit = pointer;     buttonDefaultVisual = 40; hit = 44;
buttonSmVisual = 36;                         buttonSmVisual = 36; hit = 44;
buttonLgVisual = 44;                         buttonLgVisual = 44; hit = 44;
```

`Input` is intentionally different from `Button`: the native field itself must become 44pt because its password and clear actions are already `44×44` inside the current 40pt shell (`mobile/src/components/ui/input.tsx:257-270`, `mobile/src/components/ui/input.tsx:276-315`; `mobile/src/components/ui/search-field.tsx:81-106`). Buttons already preserve the web's visual sizes while calculating hit slop up to 44pt (`mobile/src/components/ui/button.tsx:51-56`, `mobile/src/components/ui/button.tsx:225-245`).

**RECOMMEND:** Treat 44pt as the minimum *interactive footprint*, but enlarge the visible field to 44pt where a caret, text, and embedded actions share the box; this preserves the web's density without reproducing mouse-sized phone controls.

### Focus, error, selection, and branded form context

The web focus treatment is a visual layer, not a border-color swap: Input and Textarea retain `border-input` and add `focus-visible:ring-1 ring-ring` (`web/src/components/ui/input.tsx:14-18`, `web/src/components/ui/textarea.tsx:12-16`). Native should use a nested animated wrapper or an absolutely positioned halo so the resting edge does not disappear. This is a StyleSheet/Reanimated change, not a library requirement.

Web auth applies both classes at the root:

```tsx
<main className="grimoire pressroom ... bg-void"> // web/src/components/onboarding/auth-shell.tsx:53-55
```

That changes radii to 6, button type to sigil 12/tracking1.2/uppercase, labels to sigil 11/tracking1.76/uppercase/ash, inputs to sigil, quiet buttons to transparent/bone/lineStrong, and disabled buttons to transparent/ash/lineG at opacity1 (`web/src/app/globals.css:197-235`). Native defines the correct `grimoireColors` but exposes only light/dark `Theme` objects (`mobile/src/theme/colors.ts:102-152`, `mobile/src/theme/theme.ts:23-50`). `AuthShell`, Input, and its plate therefore read ordinary theme colors (`mobile/src/components/auth/auth-shell.tsx:74-106`; `mobile/src/components/ui/input.tsx:180-193`, `mobile/src/components/ui/input.tsx:243-251`).

**RECOMMEND:** Add a scoped auth/pressroom style context rather than a third user-selectable theme: `background #000000`, `foreground #F2EDE2`, `card #120F0E`, `muted #191514`, `mutedForeground #A39A8C`, `input rgba(242,237,226,.26)`, `border rgba(242,237,226,.13)`, `ring/error #FF453A`, r6 controls, sigil labels/buttons/inputs, and the web quiet/disabled recipes. The literal targets already exist in `pressroomColors`/`grimoireColors` (`mobile/src/theme/colors.ts:102-152`).

**RECOMMEND:** Change app `selectionColor` from `ring` to `brandAccent`, and auth selection to fixed `hellfire #E11E15`; web uses brand selection globally and hellfire/void in grimoire (`web/src/app/globals.css:237-240`, `web/src/app/globals.css:440-446`).

## 3. Branding parity, including logo colors
