# term-conformance

Automated grid-state conformance testing for spawn's browser terminal.

spawn ships raw PTY bytes end-to-end from the host daemon to the browser; all
terminal emulation happens client-side in xterm.js (`web/` uses
`@xterm/xterm` 5.5). This harness proves that emulation behaviorally matches
**iTerm2** — characters, colors, attributes, cursor, alt-screen, title — not
pixels or fonts.

## Architecture

```
corpus/cases/*.bin ──┬──> sut-xterm/run.mjs (@xterm/headless 5.5.0) ──> out/sut/*.json
 (raw VT bytes,      │
  corpus/manifest)   ├──> oracle-iterm2/iterm2_runner.py (macOS) ──────> fixtures/*.json
                     └──> oracle-pyte/pyte_runner.py (anywhere) ───────> fixtures-pyte/*.json

          differ/differ.py + driver.py: compare two JSON dirs cell-by-cell,
          render report, apply known-divergences allowlist.
```

- **Schema** (`schema/grid-state.schema.json`, notes in `schema/schema.md`):
  versioned per-cell snapshot of the visible screen. All producers emit the
  same shape, so any pair of emulators can be diffed.
- **Corpus** (`corpus/`): 58 raw-byte cases generated by
  `corpus/build_corpus.py` — cursor movement (CUP/CUU/CUD/CUF/CUB, CNL/CPL,
  CHA/HPA/VPA, CHT/CBT), DECSC/DECRC and CSI s/u, SGR 16/256/truecolor +
  every attribute + partial resets, DECAWM wrapping + pending-wrap edge
  cases, DECSTBM scroll regions + SU/SD, ED/EL/ECH + background-color-erase,
  DECALN, REP, alt screen (1049), IL/DL/ICH/DCH incl. region boundaries,
  tabs (HTS/TBC), DECOM incl. out-of-region clamping, RI/NEL/IND, RIS,
  DECSCUSR, wide CJK incl. torn-cell overwrites, emoji width (Unicode 11),
  combining marks incl. end-of-line, OSC 0/2 titles, OSC 8 hyperlinks,
  OSC 52 clipboard, OSC 1337 passthrough, scrollback overflow, and a
  repaint-convergence pair modeling checkpoint-replay reattach (the manifest
  `equivalences` entry makes the driver assert both grids are identical).
- **SUT** (`sut-xterm/`): Node runner on `@xterm/headless` — the same
  emulation core and version the web client renders with, instantiated with
  the web client's exact emulation options and Unicode 11 width tables via
  the shared config module `web/src/components/terminal/xterm-config.mjs`
  (single source of truth for web + harness).
- **Oracle** (`oracle-iterm2/`): records fixtures from a live iTerm2 via its
  Python API (`async_inject` + `async_get_screen_contents`). macOS only;
  record/replay design because CI is Linux. *Reviewed but unexecuted* — see
  its README.
- **Pseudo-oracle** (`oracle-pyte/`): pyte implementation so the whole
  pipeline runs end-to-end on Linux today. Its genuine divergences from
  xterm.js (documented in `known-divergences.json`) double as proof that the
  differ catches real behavioral differences.

## Run it (Linux, this repo)

Prereqs: `node` ≥ 20, `uv`. First run auto-installs npm/python deps.

```sh
cd tools/term-conformance
uv run driver.py full-run --report reports/sample-xterm-vs-pyte.txt
```

Other subcommands:

```sh
uv run driver.py run-sut [--case NAME] [--out DIR]         # SUT only -> out/sut/
uv run driver.py record-fixtures --oracle pyte             # -> fixtures-pyte/
uv run driver.py compare --expected fixtures-pyte --actual out/sut [--report F]
```

**Exit codes** (compare/full-run): `0` = every case passes or fails only in
ways listed in `known-divergences.json`; `1` = unexpected divergence **or** a
listed case now passes (stale allowlist entry — remove it); `2` = pipeline
error (runner crash, missing fixture, schema violation). CI should require 0.

Current status: 58 corpus cases + 2 repaint-equivalence assertions —
43 exact matches, 17 known pyte divergences (no alt-screen buffer, no
CSI s/u, no SGR dim, no DECSTBM cursor homing, wide-char handling at the
right edge and on partial overwrite, no SU/SD/REP/HPA/CHT/CBT/OSC 8,
NEL without CR, DECOM out-of-region no-op, ED without BCE, DECALN without
margin reset). See `reports/sample-xterm-vs-pyte.txt`.

## Record real iTerm2 fixtures (Mac)

See [`oracle-iterm2/README.md`](oracle-iterm2/README.md). Short version:
enable the iTerm2 Python API, `uv sync --group iterm2`, run
`uv run --group iterm2 driver.py record-fixtures --oracle iterm2`, commit
`fixtures/*.json`, then on Linux/CI:

```sh
uv run driver.py run-sut
uv run driver.py compare --expected fixtures --actual out/sut
```

`known-divergences.json` is pyte-specific; start the iTerm2 comparison with an
empty allowlist and only add entries after manually verifying intent.

## Schema versioning

`version` (currently 1) is a monotonic integer; consumers reject unknown
versions and the differ refuses to compare mismatched ones. Fields whose
absence means null/wildcard (like the v1.1 `cursor.style`/`cursor.blink`
DECSCUSR observations) may be added without a bump; additive fields with
concrete defaults bump the version. Fixtures carry the version they were
recorded with, so old recordings stay honest. Full rules in
`schema/schema.md`.

## Layout

```
schema/            grid-state schema + prose spec
corpus/            build_corpus.py, manifest.json, cases/*.bin
sut-xterm/         @xterm/headless runner (npm, pinned 5.5.0)
oracle-iterm2/     iTerm2 recorder (macOS, reviewed-unexecuted) + setup docs
oracle-pyte/       pyte pseudo-oracle runner
differ/            cell-by-cell comparison + report rendering
common/            shared schema helpers (compaction, validation, color semantics)
driver.py          entrypoint: run-sut | record-fixtures | compare | full-run
known-divergences.json   expected xterm-vs-pyte failures (allowlist)
fixtures-pyte/     committed pyte fixtures (regenerate via record-fixtures)
fixtures/          reserved for real iTerm2 recordings
reports/           committed sample report
out/               scratch SUT output (gitignored)
```
